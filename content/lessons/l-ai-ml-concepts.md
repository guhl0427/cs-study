> 一句话定义：机器学习不是人写规则，而是让算法从数据里自己学出规律——规律装进模型，就能对没见过的新数据做预测。

## 概念讲解

### 从 if-else 的困境说起：规则永远写不完

做一个垃圾邮件过滤器，人写规则的第一反应：

```python
if "中奖" in text or "免费领取" in text:
    return "垃圾邮件"
```

能跑，但立刻进入军备竞赛：发件人写成「中 奖」「仲獎」「中★奖」，你加空格变体；他换成图片文字，你上 OCR；他模拟正规邮件措辞，规则越加越多、互相打架，最后没人敢动那坨 if-else。**规则有限，骗术无限**——凡是「套路会变、样本海量」的问题，人写规则都会输。

机器学习把方向反过来：不再写规则，而是给算法几万封**已经标好**「垃圾/正常」的邮件，让它自己从数据里提炼规律：

```text
人写规则：  人脑 ──想规则──→ 规则 ──套用──→ 新邮件
机器学习：  标注数据 ──算法提炼──→ 模型 ──套用──→ 新邮件
                     ↑ 规律是从数据里长出来的，会随数据更新
```

新骗术出现 → 重新标注新样本 → 重训模型即可，不用重写代码。这就是「从数据学规律」的全部含义。

### 监督与无监督：有没有「标准答案」是分水岭

判断手头任务属于哪一流派，只看一个问题：**每条数据有没有人工标注的正确答案？**

| 流派 | 有无标签 | 典型子任务 | 真实场景 ×2 |
| ---- | ---- | ---- | ---- |
| 监督学习 | 有 | 分类（答案是类别） | 垃圾邮件识别（垃圾/正常）；银行风控（放贷/拒贷） |
| 监督学习 | 有 | 回归（答案是数字） | 二手房估价（价格）；预测下月销量（数值） |
| 无监督学习 | 无 | 聚类（自动分群） | 电商把用户分群做差异化运营；新闻自动聚合成话题 |

记忆锚点：**分类答「是哪类」，回归答「是多少」，聚类答「能分成几堆」**。分不清时问自己：如果模型输出错了，你手里有没有一个「正确答案」可以对照？有→监督；没有、只能事后人工解读→无监督。

### 特征与标签：术语表（后面每课都在用）

| 术语 | 含义 | 垃圾邮件例子里对应 |
| ---- | ---- | ---- |
| 样本 sample | 一条数据 | 一封邮件 |
| 特征 feature | 判断用的线索（输入） | 词频、发件人域名、正文链接数 |
| 标签 label | 要预测的答案（输出） | 垃圾 / 正常 |
| 模型 model | 学出来的可预测函数 | 「词频→判垃圾」的整套规律 |
| 训练 train | 喂标注数据让算法提炼规律 | 用 1 万封已标注邮件学 |
| 预测 predict | 对新数据套用模型 | 判定今天新收到的邮件 |

### 训练集与测试集：考题绝不能提前做过

把数据切两份：**训练集**给模型学，**测试集**留作考试，考完之前模型一眼都不许看。为什么？让模型做它背过的题，分数只会虚高——就像平时背答案的学生，你以为他满分实力，其实考不了真卷。

```text
300 条数据 ──随机切分──→ 70% 训练集（210 条）   模型学习用
                       30% 测试集（90 条）     上锁，最后才考
```

切分必须是随机的（`train_test_split` 默认打乱），否则前 70% 若恰好都是某一类，学不好也考不好。

### 过拟合 = 背题，欠拟合 = 没学会

模型最常见的两种病，用「训练准确率 vs 测试准确率」两个数字就能确诊：

| 现象（训练分 / 测试分） | 诊断 | 类比 | 药方 |
| ---- | ---- | ---- | ---- |
| 0.99 / 0.63 | **过拟合** | 背题：平时满分，换卷就崩 | 降低模型复杂度、加数据、正则化 |
| 0.61 / 0.60 | **欠拟合** | 根本没学会 | 加特征、加大模型容量 |
| 0.85 / 0.83 | 健康 | 学会了，且能举一反三 | 可以交付 |

判别口诀：**两分差距大 → 过拟合；两分都低 → 欠拟合**。过拟合的本质：模型太能干，把训练数据里的噪声和巧合也当成规律背了下来；欠拟合的本质：模型太弱，连主要规律都没抓住。下面亲手制造一次。

### 常见算法一句话扫盲

| 算法 | 一句话 | 什么时候想到它 |
| ---- | ---- | ---- |
| 线性回归 | 拟一条直线/超平面预测数值 | 特征与答案大致线性（面积→房价） |
| 决策树 | 一串 if-else，但它自己从数据里学出来 | 表格数据、想要可解释的规则 |
| KNN | 新样本看最近的 K 个邻居投票 | 小数据快速上手、边界不规则 |
| 聚类 | 无标签自动分堆（如 K-Means） | 用户分层、探索数据结构 |

下一课你会看到：这四个算法在 sklearn 里用法一模一样（fit/predict），选哪个只是换一行。

### 评估直觉：准确率不是全部

假设 99% 的邮件本来就正常。一个无脑模型「永远判正常」准确率高达 99%——但一封垃圾邮件都抓不到，业务上毫无价值。这叫**类别不平衡**：多数类会撑高准确率。更诚实的问法是「垃圾邮件里，模型抓到了多少」（召回率）。入门阶段记住直觉即可：**只报一个准确率时，先问类别比例；指标要结合业务问题选**。

## 代码示例

主线任务：**手工制造一次过拟合**。用决策树做深度对比实验，亲眼看着「训练分冲到 1.0、测试分反而下滑」——这是机器学习最重要的一课，比任何定义都有效。装了 sklearn 跑真代码；没装也完整可读（输出已标注，另附文字推演）。全程约 30 分钟。

### 实验设计

- 用 `make_classification` 造一批**有噪声**的数据：300 条、20 个特征（只有 4 个有用），`flip_y=0.2` 表示 20% 的标签故意标错——真实世界的数据永远有噪声。
- 训练集（210 条）训练，测试集（90 条）考试。
- 控制变量只有一个：**决策树最大深度**（模型复杂度旋钮）。深度越大，模型越能「逐条背样本」。

```python
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
from sklearn.metrics import accuracy_score

# 造数据：20% 标签故意标错（噪声），逼模型在「学规律」和「背噪声」之间做选择
X, y = make_classification(n_samples=300, n_features=20, n_informative=4,
                           flip_y=0.2, random_state=7)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=42)
print(X_train.shape, X_test.shape)          # (210, 20) (90, 20)

print("深度      训练准确率   测试准确率")
for d in [1, 2, 4, 8, None]:                # None = 不限深度，可劲儿背
    model = DecisionTreeClassifier(max_depth=d, random_state=0)
    model.fit(X_train, y_train)             # 只喂训练集——考试卷上锁
    tr = accuracy_score(y_train, model.predict(X_train))
    te = accuracy_score(y_test, model.predict(X_test))   # 只用测试集打分
    print(f"{str(d):>4}      {tr:.3f}        {te:.3f}")
```

### 预期输出（sklearn 1.9.1 实测；换版本数字微动，形态不变）

```text
深度      训练准确率   测试准确率
   1      0.762        0.833
   2      0.795        0.811
   4      0.919        0.778
   8      0.995        0.778
 不限深    1.000        0.767
```

### 读结果：一条 U 形曲线的教训

1. **训练分随深度单调上升到 1.000**：不限深度的树有足够多的 if-else，把 210 条训练样本**连标签噪声一起背了下来**——训练集上它「永远全对」，但其中约 20% 背的是错误答案。
2. **测试分反而从 0.833 滑到 0.767**：背下来的噪声到考试卷上全是错的，记忆力越强错得越狠。0.833 - 0.767 ≈ 6.6 个百分点，就是过拟合税。
3. **深度 1 的树训练分仅 0.762，测试分却最高 0.833**：它弱到背不了题，只能抓最主要的规律。测试分最高的深度在中间（2 附近）——这就是「模型复杂度要匹配数据」的甜点区。

对照前文数字表：不限深度的树就是典型的「0.99 / 0.63」过拟合画像；深度 1 略偏欠拟合但泛化最稳。**记住结论：看测试分，别信训练分。**

### 无 sklearn？文字推演一遍同样的道理

拿 6 条训练样本（2 个特征），混进 2 条标错的噪声：

```text
 x1    x2   标签
 3.1   4.2   猫
 3.2   4.1   猫
 2.9   3.8   猫
 7.5   8.1   狗
 7.4   7.9   狗
 2.0   9.0   狗    ← 噪声：真猫标成了狗

浅树（深度 1）只能学一个大方向：
  if x1 < 5: 猫  else: 狗
  → 新样本 (3.0, 4.0) 判猫 ✓（噪声影响不到它）

深树（不限深）要训练集 100% 全对，只能把噪声也写进规则：
  if x1 < 5 且 x2 < 9.5: 猫
  elif x1 < 5 且 x2 >= 9.5: 狗   ← 这条分支专门"记住"那条噪声
  else: 狗
  → 新样本 (2.1, 8.8)（真猫）判成狗 ✗ 把噪声当成了规律
```

深树的每条奇怪分支都是「为某一条训练样本定制」的——这就是「背题」在规则层面的样子。真实实验里 20% 的标签噪声放大了同样的机制，于是训练分 1.0、测试分下滑。

### 一个加餐观察：类别比例先看一眼

```python
import numpy as np
print(np.bincount(y))        # [152 148]  两类几乎各半 → 准确率可用
# 若输出是 [285 15]（严重不平衡），就得改用召回率等指标，见概念讲解最后一节
```

## 常见坑

1. **坑 1：没划分训练/测试集就报准确率**。现象：同事说「模型 99% 准确」，其实是在训练数据上评的。原因：背题成绩，无意义。排查：第一句话问「测试集怎么划分的」；自己动手时把 `train_test_split` 放在流程第一步。
2. **坑 2：测试集偷偷参与调参**。现象：反复用测试分挑模型、调超参，最终测试分 0.93，上线却只有 0.80。原因：测试集被你反复「偷看」，成了隐形训练集，成绩虚高。排查：严格流程再切一块**验证集**用于调参，测试集只在最后碰一次；或用下一课的交叉验证。
3. **坑 3：把回归任务当分类做**。现象：预测价格却输出「高/中/低」。原因：任务定性错了。排查：先问「答案是一个数字（回归）还是一个类别（分类）」，再选算法与评估指标。
4. **坑 4：类别不平衡时只看准确率**。现象：模型准确率 97%，业务方投诉「一个异常单都没抓到」。原因：异常只占 3%，全判正常也有 97%。排查：先 `bincount` 看类别比例；不平衡时补看召回率、精确率或混淆矩阵。
5. **坑 5：随机种子不固定，结果没法复现**。现象：每次运行准确率都不一样，讨论不起来。原因：切分和模型初始化都带随机性。排查：`train_test_split(random_state=42)`、模型构造时 `random_state=0`，教学与调试阶段一律固定。
6. **坑 6：把「测试分低」一律归因为模型不行**。现象：测试分 0.65 就急着换更复杂的模型。原因：也可能是特征太弱（欠拟合要加特征）、或数据标签本身噪声大（本实验测试分理论上限就被 20% 噪声压住）。排查：先想「理论准确率天花板是多少」，再看数据质量，最后才是换模型。

## 小练习

1. 「预测某用户下个月会不会流失」是分类还是回归？列出 3 个可用的特征（提示：从用户行为数据里找线索）。
2. 把实验的 `flip_y` 改成 0（标签干净）重跑，观察深度 1 和不限深的测试分变化，并用「噪声」解释为什么过拟合消失了。
3. 同事的模型训练准确率 0.71、测试准确率 0.70。它得了什么病？给出两条对应的「药方」。
4. **综合任务**：把实验改造成「深度扫描报告」——深度取 1 到 10 的全部整数，输出每个深度的训练/测试分；找出测试分最高的深度；再用一句话向非技术同事解释「为什么我们选这个深度」。跑通它，你就完整复现了一次真实世界的模型选型过程。
