> 一句话定义：快的存储贵、慢的存储便宜，所以计算机把它们叠成金字塔，再用缓存加局部性原理，让程序「感觉上」住在一整套又快又大的存储里。

## 概念讲解

存储金字塔，相邻两层速度差 10~1000 倍（延迟为约值）：

```text
寄存器      ~0.3 ns    几十字节          手里正在算的数
L1 缓存     ~1 ns      几十 KB           桌上摊开的笔记
L2/L3 缓存  ~4~15 ns   几百 KB~几十 MB   身旁书架
内存 DRAM   ~100 ns    GB 级             家里储藏室
SSD         ~0.1 ms    TB 级             楼下超市
机械磁盘    ~10 ms     TB 级还便宜       郊外仓库
```

类比：你在书桌前写作业。伸手拿笔（寄存器）瞬间完成；起身去书架取一本书的时间，够你伸手拿桌上东西几百次——所以「把常用的搬到桌上」，就是缓存的全部思想。

**缓存能生效，靠的是局部性原理**——程序访问内存的两条经验规律：

- **时间局部性**：刚访问过的数据，很快会再访问（循环变量、反复用的计数器）。
- **空间局部性**：访问了某地址，旁边的地址很快也会被访问（挨个遍历数组）。

**缓存行（Cache Line）是缓存搬运的最小单位，典型 64 字节**：哪怕只读 1 个字节，硬件也把整块 64 字节搬上来。这对程序员是好消息——只要按地址连续访问，「邻居」全部免费搭车：读 `a[0]` 时，`a[1]`~`a[15]`（int 每个 4 字节，16 个正好一行）已经进了缓存。命中（数据已在缓存）约 1ns；未命中就得去下一层，一次约 100ns——够 ALU 干几百条指令。

于是有那道经典面试题：**按行遍历二维数组比按列快一个数量级**。二维数组在内存里是按行连成一条的：

```text
内存：[a[0][0] a[0][1] ... a[0][999]] [a[1][0] ...] ...
按行：地址每次 +4 字节 → 一个缓存行喂 16 次访问，几乎全命中
按列：地址每次跳 4000 字节 → 一个缓存行只喂 1 次，几乎全未命中
```

对程序员的实际意义：**数据布局的收益常常大于算法微调**。优先用连续内存（数组优于链表式乱跳），把一起用的数据放在一起（C 结构体对齐与字段排序、列式存储，都源于此）。这思想放到慢速层同样成立：数据库 B+ 树把节点做成「一个磁盘页」大小，一次 I/O 搬回一整页键值，树矮、I/O 少；CPU 硬件的「预取」和数据库的预读，则是在猜你下一步要什么、提前搬进快的那层。

## 代码示例

亲手复现「按行快、按列慢」：

```python
import time

N = 1024
grid = [[j for j in range(N)] for _ in range(N)]   # 1024x1024 二维列表

t0 = time.perf_counter()
total = 0
for row in grid:            # 按行：顺着内存方向挨个走
    for v in row:
        total += v
t_row = time.perf_counter() - t0

t0 = time.perf_counter()
total = 0
for j in range(N):          # 按列：每步跳一整行 1024 个元素
    for i in range(N):
        total += grid[i][j]
t_col = time.perf_counter() - t0

print(f"按行 {t_row:.3f}s, 按列 {t_col:.3f}s")
# 典型输出：按行 0.190s, 按列 0.680s —— 访问次数完全相同，纯布局差异
```

说明：Python 的列表存的是指针、对象又散落在堆上，缓存效应打了折扣；同样的实验换成 C 的连续数组，差距能拉到 5~10 倍以上。但方向一致——**访问顺序决定缓存命中率**。

## 常见坑

1. **坑 1：以为内存访问都一样快**。一次未命中约 100ns，瓶颈常常是访存不是计算。排查：热点循环里改成连续布局，减少指针追逐。
2. **坑 2：嵌套循环内外层顺序随手写**。大数组上内外层一换就是数量级差距。排查：让最内层下标沿着内存方向连续变化。
3. **坑 3：以为加了缓存就一定快**。缓存生效的前提是局部性——大哈希表乱跳、洗乱顺序的指针数组这类随机访问，缓存帮不上忙还白搬数据。排查：先看访问模式是不是「成片」的。

## 小练习

1. 判断下列访问各体现哪种局部性：① 反复读写同一个计数器；② 遍历数组求和；③ 刚加载过的函数代码马上又被调用。
2. 把示例在你机器上跑一遍，记录按行/按列的倍数；再把 N 改成 2048 重跑，观察差距是否更明显，并解释原因。
3. 思考题：B+ 树的节点为什么做成「一个磁盘页」那么胖，而不是越小越灵活？试着只用「局部性」和「每层延迟差几百倍」两句话回答。
