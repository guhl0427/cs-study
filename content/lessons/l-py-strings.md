> 一句话定义：字符串是**不可变的字符序列**——所有「修改」其实都是造新字符串，掌握索引切片与方法全景，就能处理 90% 的文本工作。

## 概念讲解

### 不可变性：为什么改一个字符要重建整个字符串

先看一个必然报错的操作：

```python
s = "python"
s[0] = "P"    # TypeError: 'str' object does not support item assignment
```

原因：Python 的字符串一旦创建就**不可变（immutable）**。可以把它想成**刻在石碑上的字**——刻完就改不了，想改只能换一块新石碑重新刻；而列表是**白板**，擦掉重写随你。所以所有看似「修改」字符串的方法（`lower`、`replace`、`strip`）都**返回一个新字符串**，原字符串纹丝不动：

```python
s = "  Python  "
s.strip()          # 返回新串 "Python"，但没人接住它，立刻被丢弃
s2 = s.strip()     # 正确：用变量接住新串
print(s)           # "  Python  "  原字符串没变
print(s2)          # "Python"
```

为什么这样设计？三个理由：**其一，安全共享**——字符串在程序里被到处传递（函数参数、字典键），如果任何一处能改它，其他使用处全部遭殃；不可变意味着谁也改不了，随便传。**其二，能当字典键**——字典键必须稳定不变（下一课细讲），字符串靠不可变性获得了这个资格。**其三，省心**——你不用担心某个函数「顺手」改坏了你传进去的文本。代价是频繁拼接效率略低，但入门阶段的场景完全无感。

### 索引与切片：负索引与步进

字符串既是序列就能按下标取字符，Python 还支持**负索引**（从尾部倒数）：

| 表达式 | 结果 | 说明 |
| ---- | ---- | ---- |
| `"Python"[0]` | `'P'` | 正向从 0 起 |
| `"Python"[-1]` | `'n'` | 负索引从 -1 起，`-1` 永远是最后一个 |
| `"Python"[1:4]` | `'yth'` | 切片含头不含尾，取下标 1、2、3 |
| `"Python"[:3]` | `'Pyt'` | 省略起点 = 从头开始 |
| `"Python"[3:]` | `'hon'` | 省略终点 = 到末尾为止 |
| `"Python"[::2]` | `'Pto'` | 步长 2，隔一个取一个 |
| `"Python"[::-1]` | `'nohtyP'` | 步长 -1，从尾往头走 = **反转** |

切片是「含头不含尾」：`s[1:4]` 取到下标 4 之前为止，好处是 `s[:3]` 和 `s[3:]` 正好拼回原串、`len(s[a:b]) == b - a` 永远成立，数学上很干净。三个高频技巧记住：`s[-1]` 取末字符、`s[::-1]` 反转、`s[:-1]` 去掉末字符。切片越界**不报错**（`"abc"[10:]` 得空串），只有单字符索引越界才报 `IndexError`。

### 常用方法全景：按场景归类

字符串方法几十个，死背必忘；按「你拿到一段文本想干什么」分三类，随用随查：

| 场景 | 方法 | 示例 | 结果 |
| ---- | ---- | ---- | ---- |
| **清洗** | `strip()` | `"  hi \n".strip()` | `'hi'`（去掉两端空白） |
| | `lower()` / `upper()` | `"PyThon".lower()` | `'python'` |
| | `replace(old, new)` | `"1-2-3".replace("-", ":")` | `'1:2:3'` |
| **切分** | `split()` | `"a b  c".split()` | `['a', 'b', 'c']` |
| | `split(sep)` | `"a,b,c".split(",")` | `['a', 'b', 'c']` |
| | `join(list)` | `",".join(['a', 'b'])` | `'a,b'`（split 的逆操作） |
| **查找** | `find(sub)` | `"hello".find("ll")` | `2`（找不到返回 -1） |
| | `in` 运算符 | `"ll" in "hello"` | `True`（只判存在，最常用） |
| | `startswith(sub)` | `"py3".startswith("py")` | `True` |
| | `count(sub)` | `"banana".count("an")` | `2` |

三个要点：**清洗类和切分类的方法都返回新对象**（字符串方法返回新串，`split` 返回新列表），必须赋值接住；`strip()` 只处理**两端**，中间的空白它不管；`split()` 不带参数时按「任意连续空白」切且自动忽略首尾空白，是处理脏数据的首选，而 `split(" ")` 严格按单个空格切、会产生空字符串——这个区别第 5 个坑里专门演示。

### f-string 进阶：对齐、精度、千分位

上一课只用了 `:.1f`，f-string 的完整能力是**格式说明符**：冒号后跟「填充对齐 + 宽度 + 精度/类型」。做报表输出时极其好用：

| 写法 | 示例 | 输出 | 用途 |
| ---- | ---- | ---- | ---- |
| `:>8` | `f"{42:>8}"` | `'      42'` | 右对齐占 8 位（数字默认右对齐） |
| `:<10` | `f"{'ab':<10}"` | `'ab        '` | 左对齐占 10 位（字符串默认左对齐） |
| `:^10` | `f"{'hi':^10}"` | `'    hi    '` | 居中 |
| `:.2f` | `f"{3.14159:.2f}"` | `'3.14'` | 保留 2 位小数 |
| `:,` | `f"{1234567:,}"` | `'1,234,567'` | 千分位分隔（金额必备） |
| `:.1%` | `f"{0.756:.1%}"` | `'75.6%'` | 小数变百分数 |

这些说明符还能组合（`f"{total:>10,.2f}"` 右对齐 + 千分位 + 两位小数），做「每行等宽、列列对齐」的文本报表不费吹灰之力。

### 转义字符与原始字符串：反斜杠的脾气

反斜杠 `\` 在字符串里有特殊含义——它转义下一个字符：

| 写法 | 含义 | 示例输出 |
| ---- | ---- | ---- |
| `\n` | 换行 | 分行打印 |
| `\t` | 制表符（Tab） | 对齐输出 |
| `\\` | 一个真正的反斜杠 | `\` |
| `\"` | 引号（字符串用双引号包时的救急） | `"` |

由此产生 Windows 新手第一大坑：路径 `C:\new\test` 里的 `\n` 和 `\t` 会被当成换行和制表符！写文件路径时**必须用原始字符串**——引号前加 `r`，让反斜杠失去超能力：

```python
path = "C:\new\test"    # 错：\n 变换行、\t 变制表符
path = r"C:\new\test"   # 对：r 前缀，原样保留反斜杠
```

另一个实用点：字符串想同时包含单双引号时，外面用三引号包（`"""..."""`），还能顺便跨行——文档字符串就是靠它实现的。

### 编码一句话：UTF-8 与中文

Python 3 的字符串内部以 Unicode 存储，`len("中文")` 得 2（按字符数，不按字节），中英文可以自由拼接、切片、比较，不需要你操心编码。只有两个时刻会碰到编码：**读写文件**时要显式指定 `encoding="utf-8"`（文件课细讲）；报 `UnicodeDecodeError` 时，意味着文件的真实编码和你猜的不一致——UTF-8 是当今绝对主流，默认选它。

## 代码示例

主线任务：**写一个「脏数据清洗器」**。真实世界的文本数据总是脏的：多余空白、大小写混乱、分隔符不统一。本任务把一段格式混乱的原始文本清洗成规范的字符串列表并输出对齐报表。跟着做约 20 分钟。

### 第 0 步：看清脏数据长什么样

假设你从表单导出了一批用户名，存成一个多行字符串：

```python
raw = "  alice ,BOB ,  charlie\nDavid , eve ,FRANK "
print(repr(raw))    # repr() 能显示隐藏字符：空白、\n 都看得见
```

运行结果：

```text
'  alice ,BOB ,  charlie\nDavid , eve ,FRANK '
```

问题清单：名字大小写不统一、逗号前后有多余空格、整串混着换行符、首尾有垃圾空白。目标格式：`["Alice", "Bob", "Charlie", "David", "Eve", "Frank"]`——首字母大写、无多余空白、干净列表。

为什么先 `repr()`：直接 print 看不出 `"\n"` 和空格的存在，`repr()` 把隐藏字符显形，是清洗文本的第一诊断工具。

### 第 1 步：整串切开成列表

用无参 `split()` 把整串按空白（空格 + 换行）切开，得到「半成品」：

```python
parts = raw.split()
print(parts)
```

运行结果：

```text
['alice', ',BOB', ',', 'charlie', 'David', ',', 'eve', ',FRANK']
```

坏消息：逗号粘在名字上、还切出了孤零零的 `,`。原因：空白切分不解决逗号问题。思路升级——**先把逗号替换成空格，再切**：

```python
parts = raw.replace(",", " ").split()
print(parts)
```

运行结果：

```text
['alice', 'BOB', 'charlie', 'David', 'eve', 'FRANK']
```

为什么这个顺序：`replace` 造出新字符串（不可变性！），新串再被 `split` 切成列表——方法的**链式**协作是字符串处理的标准节奏。

### 第 2 步：逐个清洗每一条

对列表里每个名字做「去空白、转小写」的规范化，为下一步统一格式打底：

```python
cleaned = []
for name in parts:
    name = name.strip().lower()   # 链式调用：先去两端空白，再转小写
    if name:                      # 空字符串（全空白的名字）直接跳过
        cleaned.append(name)
print(cleaned)
```

运行结果：

```text
['alice', 'bob', 'charlie', 'david', 'eve', 'frank']
```

为什么 `if name:` 能判空：空字符串 `""` 在布尔判断里为假，这一个条件就过滤掉了所有「纯空白」垃圾项——Python 的惯用手法。

### 第 3 步：统一为首字母大写

```python
names = [name.capitalize() for name in cleaned]
print(names)
```

运行结果：

```text
['Alice', 'Bob', 'Charlie', 'David', 'Eve', 'Frank']
```

`capitalize()` 把每个单词首字母大写、其余小写；这里用列表推导式一步生成新列表——推导式细节下一课展开。

### 第 4 步：组装成完整清洗器并输出报表

把四步串成完整程序（保存为 `clean.py`）：

```python
raw = "  alice ,BOB ,  charlie\nDavid , eve ,FRANK "
print(repr(raw))                       # 第 0 步：诊断原始数据

parts = raw.replace(",", " ").split()  # 第 1 步：逗号换空格再切分
cleaned = []
for name in parts:                     # 第 2 步：逐条清洗
    name = name.strip().lower()
    if name:
        cleaned.append(name)
names = [name.capitalize() for name in cleaned]  # 第 3 步：首字母大写

print(f"清洗前共 {len(raw)} 个字符，清洗后 {len(names)} 条有效记录")
print("-" * 32)
for i, name in enumerate(names, start=1):
    print(f"{i:>2}. {name:<12} (原样: {parts[i-1]!r})")
```

运行结果：

```text
'  alice ,BOB ,  charlie\nDavid , eve ,FRANK '
清洗前共 44 个字符，清洗后 6 条有效记录
--------------------------------
 1. Alice        (原样: 'alice')
 2. Bob          (原样: 'BOB')
 3. Charlie      (原样: 'charlie')
 4. David        (原样: 'David')
 5. Eve          (原样: 'eve')
 6. Frank        (原样: ',FRANK')
```

两处新语法：`enumerate(names, start=1)` 同时给出序号和元素（自己维护计数器是新手常见弯路）；`{parts[i-1]!r}` 里的 `!r` 等价于 `repr()`，把原样字符串带着引号显示——清洗前后对比一目了然。`{name:<12}` 左对齐占 12 位让两列严格对齐，这就是 f-string 格式说明符的实战价值。

对照第 0 步的目标格式验收：首字母大写、无空白垃圾、规范列表 + 对齐报表，全部达成。这 15 行程序覆盖了本课全部主力方法：`replace`、`split`、`strip`、`lower`、`capitalize`、`join`（练习里用）、`enumerate`、f-string 对齐——跟着做完，你已具备处理日常文本的基本功。

## 常见坑

1. **坑 1：对字符串做原地修改**。现象：`s[0] = "P"` 报 `TypeError: 'str' object does not support item assignment`。原因：字符串不可变，下标只能读不能写。对策：用切片重组 `s = "P" + s[1:]`，或需要频繁修改时先转列表 `"abc" → list("abc")` 改完再 `"".join()` 拼回。
2. **坑 2：方法调用完忘了接住返回值**。现象：`s.strip()` 单独一行执行，之后再打印 s 发现「没生效」。原因：所有字符串方法都返回新串，原串不变（不可变性）。排查：任何字符串方法调用前面必须有 `s = ...` 或作为表达式的一部分，检查返回值是否被丢弃。
3. **坑 3：`strip()` 只管两端**。现象：`"a b c".strip()` 结果是 `"a b c"`，中间空格原封不动。原因：strip 的语义就是「剥两端」，参数是「要剥的字符集合」而非前缀。对策：去中间空白用 `replace(" ", "")`；注意 `strip("()")` 会把两端所有 `(`、`)` 字符剥掉，不是剥掉一对括号。
4. **坑 4：`find` 找不到返回 -1 被当索引用**。现象：`s.find("x")` 得到 -1，随后 `s[-1]` 静默取到最后一个字符——bug 不报错但结果全错。原因：find 用 -1 表示「不存在」，而 -1 在 Python 里又是合法的负索引。对策：只判存在用 `in`；要位置且不存在就算失败时，先判 `if idx >= 0` 再用。
5. **坑 5：`split(" ")` 与 `split()` 混淆**。现象：`"a  b".split(" ")` 得到 `['a', '', 'b']`，多出空串；无参 `split()` 得到干净的 `['a', 'b']`。原因：带参 split 严格按「一个指定分隔符」切，连续分隔符产生空串。对策：清洗用户输入一律用无参 `split()`；只有格式严格受控的数据（如 CSV）才用带参版本。
6. **坑 6：Windows 路径被转义**。现象：`open("C:\temp\new.log")` 报错或行为诡异。原因：`\t`、`\n` 被解释成制表符和换行符，路径已经不是你以为的路径。对策：路径一律写原始字符串 `r"C:\temp\new.log"` 或用正斜杠 `C:/temp/new.log`；文件课的 pathlib 会更优雅地解决这件事。
