> 一句话定义：大模型是文字接龙机器——Prompt 就是接龙的开头，开头写得越清楚，它接得越准；而好的 Prompt 是像代码一样调试出来的。

## 概念讲解

### 心智模型：大模型是文字接龙机器

大模型的工作方式可以完全类比成高级版成语接龙：读入上文，预测下一个最可能的词，把它拼回去，再预测下一个……直到收尾。它没有读心术，也不会「猜你想干嘛」——它只会在你的开头条件下，接出统计上最顺的续文。

这个心智模型直接推出三条纪律：

1. **开头含糊，方向随机**。「写个周报」给模型的约束太弱，它只能接出最大众化的周报套话；你心里那家公司的具体语境它一无所知。
2. **你说得越像目标输出，它接得越像**。给它看一份你满意的输出样例，它照着接——模式复制正是接龙机器最擅长的事。
3. **Prompt 是程序参数，不是聊天寒暄**。同一个 Prompt 会进你的代码、跑一万次，所以它必须像代码一样：可测试、可复用、可迭代。

### 好 Prompt 四要素：每个都有差 vs 好对照

**要素 1 · 角色**——定视角和语气。

```text
差：帮我写个邮件。
好：你是电商客服主管。给一位等了 5 天还没收到货的顾客写一封安抚邮件。
```

差版只能接出万能模板；好版激活了「客服安抚」这一文体的大量先例——先道歉、再给补偿、给明确时效。

**要素 2 · 任务**——动词 + 对象 + 目标读者，一个都不能含糊。

```text
差：处理一下这段文字。
好：把下面 5 条流水账整理成给部门总监看的周报。
```

「处理」可以指翻译、摘要、改错……接龙方向完全未定；好版说清了「输入是什么、输出给谁看」。

**要素 3 · 约束**——圈死格式、长度和边界。

```text
差：写详细一点。
好：不超过 200 字；先结论后细节；最后单列「风险」一节，没有风险写「无」。
```

约束越可判（字数、段落顺序、必写项），输出越稳定。「写好点」「详细点」这种形容词约等于没说。

**要素 4 · 示例（few-shot）**——给它一两个「输入 → 输出」的样板照抄格式。

```text
差：用正式但不生硬的语气写，要有结构感，段落之间要有逻辑关系……（长篇格式描述）
好：
  输入：1) 订单系统上线 2) 服务器磁盘告警已处理
  输出：本周订单系统成功上线，里程碑达成。风险：服务器磁盘曾告警，已扩容，建议持续监控。
```

50 字的示例胜过 200 字的风格描述——接龙机器复制模式的能力远强于理解抽象描述的能力。

四要素合起来就是一张检查表：写完 Prompt 逐条核对，缺哪条补哪条。

| 要素 | 回答的问题 | 一句话模板 |
| ---- | ---- | ---- |
| 角色 | 它该像谁 | 「你是XX岗位的人」 |
| 任务 | 干什么、给谁 | 「把输入整理成给XX看的XX」 |
| 约束 | 边界在哪 | 「不超过X字；先X后X；必含X」 |
| 示例 | 照哪个模式抄 | 「输入A→输出A」一对真实样例 |

### 迭代思维：Prompt 是调试出来的，不是写对的

没有人一次写出完美 Prompt。正确的工作循环和调 bug 一模一样：

```text
写 v1 ──跑──→ 看输出哪里跑偏 ──对症下药──→ 写 v2 ──跑──→ …
                 │
                 ├ 结构乱   → 加约束（分节、字数）
                 ├ 重点偏   → 调任务描述（给谁看、先讲什么）
                 └ 格式不稳 → 加 few-shot 示例
```

模型的「跑偏方式」就是你的报错信息：结构乱缺约束，语气不对缺角色，格式漂缺示例。每次只改一个变量，你才知道是哪个改动起了作用。

### 分步思考：先列步骤，再给答案

让模型做数学题直接问「17 × 24 等于几」，它可能抢答一个错数；改成「先列出计算步骤，再给最终答案」，正确率明显上升。直觉还是接龙：**中间步骤写出来，等于给后续接龙铺了轨**——每一步都成为下一步的上文，模型顺着步骤走很难跑偏。这就是「思维链（CoT）」的朴素本质。适用场景：多步推理、计算、按规则判断；不适用：开放聊天（步骤反而啰嗦）。

### 幻觉：为什么会一本正经地编造

问它「推荐三本数据库经典书」，它可能给出《SQL 进阶之道》这种根本不存在的书——书名、作者、出版社齐全，读着像真的。成因回到接龙模型：它预测的是「**下一个最像的词**」，不是「下一个真的词」。训练数据里没见过你的问题对应的事实，它也会拼出语言上最通顺的答案，并且毫无愧疚感。对策四招：

1. **限定知识范围**：「只依据下面给出的资料回答」——没有外部资料可编。
2. **允许说不知道**：「资料里没有就明确说不知道」——堵死「编一个显得有用」的退路。
3. **要求给出处**：「每个结论注明来自哪份资料」——让幻觉无处藏身，也方便核查。
4. **关键事实人工核实**：模型输出是草稿不是结论，涉及法条、引用、数字一律亲自验证。

### 温度参数直觉：同一个旋钮管「敢不敢赌」

模型每接一个词，是在一个概率分布里抽样；`temperature` 控制这个分布的锋利程度。调到 0：永远选概率最高的词，同样输入输出几乎逐字相同；调高：愿意赌低概率的词，输出更有创意也更漂。

| 任务类型 | 建议 temperature | 理由 |
| ---- | ---- | ---- |
| 抽取、分类、格式转换 | 0 | 要的是每次一致，赌不起 |
| 日常问答、助手对话 | 0.5–0.7 | 稳定为主，留一点灵活性 |
| 文案、起名、头脑风暴 | 0.8–1.0 | 要的就是多样与新意 |

## 代码示例

主线任务：**同一个任务的三版 Prompt 迭代**。任务固定——把 5 条流水账整理成周报——从 v1 到 v3 逐步补要素，每版都给真实输出样例和差异分析。最后把 v3 落成可复用的代码资产。全程约 20 分钟，任何聊天窗口都能跟做。

### 固定的输入素材

```text
流水账：
1) 登录页改版上线
2) 支付接口联调完成
3) 小王请假两天
4) 测试环境数据库一度宕机
5) 新同事入职培训
```

### v1：差 Prompt（零要素）

```text
Prompt：帮我写个周报。

典型输出：
本周工作顺利，完成了多项任务，团队氛围良好，下周将继续努力……
（通篇套话，零信息量）
```

分析：接龙开头几乎没有约束，模型只能接「周报」这个概念的**大众平均版本**——它不知道有哪 5 条流水账、写给谁、要什么结构。这不是模型不行，是开头没给信息。

### v2：加角色 + 任务（激活正确视角）

```text
Prompt：你是互联网公司的项目经理。
把下面 5 条流水账整理成给部门总监看的周报：
1) 登录页改版上线 2) 支付接口联调完成 3) 小王请假两天
4) 测试环境数据库一度宕机 5) 新同事入职培训

典型输出：
本周完成登录页改版上线，支付接口联调也已收尾。人员方面小王请假两天，
新同事完成入职培训。测试环境数据库出现宕机，需要关注。
（信息点齐了，但格式、长度、重点每次跑都不同，且「风险」视角不明显）
```

分析：角色激活了「项目经理汇报」文体，任务指明了输入输出——信息密度大幅提升。但仍缺可判的约束：这次三分段、下次一大段；宕机这件事这次被提到、下次可能一笔带过。**拿去跑一次你会发现输出依然不可复现**——这就是继续迭代的信号。

### v3：加约束 + 示例（生产可用版）

```text
Prompt：你是互联网公司的项目经理。
任务：把下面流水账整理成给部门总监看的周报。
约束：不超过 200 字；先结论后细节；最后单列「风险」一节，没有风险写「无」。
示例：
  输入：1) 订单系统上线 2) 服务器磁盘告警已处理
  输出：本周订单系统成功上线，里程碑达成。风险：服务器磁盘曾告警，已扩容，建议持续监控。
流水账：
1) 登录页改版上线 2) 支付接口联调完成 3) 小王请假两天
4) 测试环境数据库一度宕机 5) 新同事入职培训

典型输出：
本周交付登录页改版与支付接口联调，项目按计划推进。
进展：新同事完成入职培训；小王请假两天，不影响进度。
风险：测试环境数据库一度宕机，建议排查稳定性，避免影响后续上线。
（结构固定、长度可控、宕机被单独突出——三版里唯一「可直接抄进邮件」的输出）
```

分析：约束把结构钉死（结论→进展→风险），few-shot 示例把语气和详略锚定。对照三版：

| 维度 | v1 零要素 | v2 角色+任务 | v3 +约束+示例 |
| ---- | ---- | ---- | ---- |
| 结构 | 无 | 隐性 | 固定三段 |
| 长度 | 不可控 | 不可控 | ≤200 字 |
| 关键信息 | 0 | 全包含 | 全包含且重点突出 |
| 每次运行可复现 | 否 | 大致稳定 | 高度稳定 |
| 定位 | 玩具 | 快速草稿 | 可进代码的生产版 |

### 落成代码资产：模板 + 填槽 + 可跑的替身调用

```python
def build_weekly_report_prompt(bullets: str) -> str:
    """v3 模板函数：流水账进、Prompt 出——可单测、可复用"""

约束：不超过 200 字；先结论后细节；最后单列「风险」一节，没有风险写「无」。
示例：
  输入：1) 订单系统上线 2) 服务器磁盘告警已处理
  输出：本周订单系统成功上线，里程碑达成。风险：服务器磁盘曾告警，已扩容，建议持续监控。
流水账：
{bullets}"""

def fake_llm(prompt: str) -> str:
    """没有 API key 也能跑的替身（返回 v3 的典型输出）。"""
    return ("本周交付登录页改版与支付接口联调，项目按计划推进。\n"
            "进展：新同事完成入职培训；小王请假两天，不影响进度。\n"

bullets = "1) 登录页改版上线 2) 支付接口联调完成 3) 小王请假两天 " \
          "4) 测试环境数据库一度宕机 5) 新同事入职培训"
print(fake_llm(build_weekly_report_prompt(bullets)))
# 输出即上面 v3 的典型输出——换真模型后只改 fake_llm 这一行
```

## 常见坑

1. **坑 1：礼貌有余、信息不足**。现象：「拜托了，随便写写就行」，输出空洞。原因：接龙开头没约束，模型接最大众化的版本。排查：对照四要素检查表逐条补齐——缺角色补角色，缺约束补约束。
2. **坑 2：一次塞多个任务**。现象：「翻译并总结并改成五言诗」输出必乱。原因：多个任务互相抢接龙方向。排查：拆成多轮对话，每轮一个任务，上一轮结果作为下一轮输入。
3. **坑 3：few-shot 示例自带错误**。现象：模型输出的格式和你的示例一样别扭。原因：它忠实复制了你的模式，包括错的部分。排查：写完示例先自查格式是否统一——示例就是最强的指令。
4. **坑 4：约束互相打架**。现象：「要详细深入，200 字以内」——模型左右为难，输出时详时略。排查：约束冲突时留一条、删一条，或改写为兼容表达（如「最多 200 字的要点清单」）。
5. **坑 5：把流畅当正确**。现象：输出读着通顺就采纳，事后发现书名/数字/事实是编的。原因：接龙机器只保证「像」，不保证「真」。排查：凡涉及事实的输出，按幻觉四招处理——限定资料、允许说不知道、要出处、人工核实。
6. **坑 6：Prompt 改来改去没有记录**。现象：「上次效果好的那版怎么写的来着？」原因：Prompt 散落在聊天记录里。排查：像管理代码一样管理 Prompt——进模板函数、进配置文件、改版留注释，效果差异记一行结论。

## 小练习

1. 把「帮我写个请假条」改写成含四要素的版本，与原版各跑一次，按三版对照表的五个维度（结构/长度/信息/可复现/定位）记录差异。
2. 让模型计算 17 × 24：一次直接问，一次要求「先列竖式步骤再给最终答案」，各跑 3 次比较稳定性，解释为什么分步更稳。
3. 构造一次幻觉：问模型一个你领域里的冷门问题（如「我们公司内部系统的 API 是什么」），观察它是否编造；然后按幻觉四招改 Prompt 重试，记录行为变化。
4. **综合任务**：选一个你真实要写的文档（周报/会议纪要/请假邮件），走完「v1 零要素 → v2 补角色任务 → v3 补约束示例」三轮迭代，每轮输出与上一轮对比，最后把它落成 `build_xxx_prompt()` 模板函数加替身测试。交付物是三版 Prompt 和一张你自己填的差异分析表。
