> 一句话定义：大模型是文字接龙机器——Prompt 就是接龙的开头，写得越清楚，它接得越准。

## 概念讲解

大模型的工作方式是**文字接龙**：读上文，预测下一个最可能的词，然后不断重复。它没有读心术——接龙的开头含糊，接出去的方向就随机。同一个「写个周报」，有人收到套话，有人收到结构清晰的报告，差别全在 Prompt。

**好 Prompt 四要素**：

| 要素 | 作用 | 例子 |
| ---- | ---- | ---- |
| 角色 | 定语气和视角 | 你是互联网公司的项目经理 |
| 任务 | 说清要做什么 | 把 5 条流水账整理成周报 |
| 约束 | 圈死格式与边界 | 不超 200 字；先结论后细节 |
| 示例（few-shot） | 给它照猫画虎的模板 | 贴一份你满意的周报 |

**迭代思维**：Prompt 是调试出来的，不是一次写对的。第一版 → 看输出哪里跑偏 → 补约束或加示例 → 再试。和调代码一样，模型的「跑偏方式」就是你的报错信息。

两个进阶技巧：**先思考再回答**——在 Prompt 里要求「先列出步骤，再给最终答案」，模型分步接龙时方向更稳，数学和逻辑题的准确率明显提升。**防幻觉**——模型会一本正经地编造论文、法条和 API 参数。对策：要求它「只依据给定资料回答，资料里没有就说不知道」并标明来源；关键事实永远自己核实。

## 代码示例

同一任务，两种问法，输出天差地别：

```text
【差的 Prompt】
帮我写个周报。

【典型输出】
本周工作顺利，完成了多项任务，团队氛围良好，下周将继续努力……
（通篇套话，零信息量）
```

```text
【好的 Prompt】
角色：你是互联网公司的项目经理。
任务：把下面 5 条流水账整理成给部门总监看的周报。
约束：不超过 200 字；先结论后细节；最后单列「风险」一节。
流水账：1) 登录页改版上线 2) 支付接口联调完成 3) 小王请假两天
        4) 测试环境数据库一度宕机 5) 新同事入职培训

【典型输出】
本周交付登录页改版与支付联调，项目按计划推进。
风险：测试环境曾宕机一次，建议排查稳定性。
（有结论、有细节、有风险——正是要的东西）
```

few-shot 示例的威力：给两个「输入 → 输出」的例子，模型会照着格式接龙，比用长篇文字描述格式有效得多——接龙机器最擅长复制模式。

四要素 Prompt 也是代码资产——写成字符串放进程序里，可测试、可复用（下一课的 API 调用就吃这个）：

```python
prompt = """角色：你是互联网公司的项目经理。
任务：把下面 5 条流水账整理成给部门总监看的周报。
约束：不超过 200 字；先结论后细节；最后单列「风险」一节。
流水账：1) 登录页改版上线 2) 支付接口联调完成 3) 小王请假两天
        4) 测试环境数据库一度宕机 5) 新同事入职培训"""
print(prompt)   # 迭代改这里，就像改代码改 bug
```

## 常见坑

1. **坑 1：礼貌有余、信息不足**。「随便写写就行」等于让模型自由发挥，输出不可控。对策：对照四要素逐条补齐，越具体越好。
2. **坑 2：一次塞多个任务**。「翻译并总结并改写成诗」输出必乱。拆成多轮对话，每轮一个任务，前一轮结果作为下一轮输入。
3. **坑 3：few-shot 示例自带错误**。示例格式不统一，模型会忠实复制你的错。写完示例先自查格式。

## 小练习

1. 把「帮我写个请假条」改写成含四要素的版本，与原版各生成一次，对比差异。
2. 让模型计算 17 × 24：一次直接问，一次要求「先列步骤再回答」，比较结果。
3. 思考题：为什么「给示例」比「给长篇描述」更能稳定输出格式？（提示：接龙机器最擅长什么？）
