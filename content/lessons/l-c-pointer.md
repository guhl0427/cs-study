> 一句话定义：指针是**存内存地址的变量**——`&` 取地址，`*` 顺着地址找到值；理解指针，就理解了程序里的数据到底「住」在哪。

## 概念讲解

把内存想成一条超长的街道，每间房子（字节）都有唯一门牌号（**地址**）：

```text
地址      房间里的值
1000  ┌──────────────┐
      │      18      │ ← int age 住在 1000 号
1004  ├──────────────┤
      │     1000     │ ← int *p 住在 1004 号，存的值是「1000 号的地址」
      └──────────────┘
```

两个运算符，一张图就够：

- `&age` —— 问「age 住在哪？」得到地址 `1000`（**取地址**）。
- `*p` —— 拿着纸条上的地址 `1000` 找到房间，取出里面的 `18`（**解引用**）。

声明一个指针的写法是 `int *p`——星号属于类型：「p 是一个指向 int 的指针」。所以下面两行是**等价**的，读的时候别被绕晕：

```c
int *p;      // 声明：p 是指向 int 的指针
*p = 18;     // 使用：往 p 指向的那个房间写入 18
```

指针最大的用途：**函数没法改调用者的变量，除非给它地址**。C 的函数参数是「复印一份」传进去的（值传递）——复印稿上怎么涂改，原件都毫发无损。想改原件，只能把「原件的地址」递过去。

### 二级指针：指向指针的指针

指针自己也是变量、也住在某个房间——所以「存指针地址的变量」就产生了**二级指针**。每个终端程序的 `int main(int argc, char *argv[])` 就是现成的例子：argv 是字符串数组，而数组名退化成「指向 char* 的指针」，类型是 `char **`：

```text
  argv (char **)
    │
    ▼
 ┌──────────────────────┐
 │ [0] ●──► "./p\0"     │
 │ [1] ●──► "Alice\0"   │    argv 指向「一堆指针」的数组，
 │ [2] ●──► "Bob\0"     │    每个指针再各自指向一个字符串
 │ [3] NULL             │
 └──────────────────────┘
 *argv      → argv[0]        （第 0 个 char*）
 **argv     → '.'            （argv[0] 的第一个字符）
 argv[1][0] → 'A'            （两级下标 = 解引用两次）
```

直觉：一级指针是「写着房间号的纸条」，二级指针是「写着抽屉位置的纸条」——顺着它先找到抽屉（数组），再从抽屉里的纸条找到房间（字符串）。除了 argv，另一个典型场景是「函数要修改指针本身」（如 `void alloc(char **out)` 往外传一块新内存）——想改什么，就传什么的地址；想改指针，就得传指针的地址。

### 函数指针：把「怎么比」当参数传

代码也住在内存里，所以函数也有地址，函数指针就是「存函数地址的变量」。标准库排序 `qsort` 的最后一个参数就是比较函数指针：

```c
#include <stdlib.h>

int cmp_int(const void *a, const void *b) {    // qsort 规定的签名
    return *(int*)a - *(int*)b;                // 负数：a 排在 b 前面
}

int arr[5] = {5, 3, 1, 4, 2};
qsort(arr, 5, sizeof(int), cmp_int);           // 把「怎么比」注入排序器
```

「排序算法不变、比较规则由调用方注入」——这就是**回调（callback）**的雏形：Python 的 `list.sort(key=...)`、JS 的 `arr.map(fn)` 都是同一个思想。本课认识一句即可，DSA 课的排序与哈希表会大量用到。

### malloc/free：堆、动态内存与泄漏初见

指针最凶险也最有用的舞台是**堆（heap）**：`malloc(字节数)` 在运行时从堆上要一块内存并返回首地址，`free(p)` 把它还回去。数组必须编译期定长，malloc 让「长度运行时才知道」成为可能——链表、树、哈希表全靠它生长：

```c
int *scores = malloc(n * sizeof(int));   // 要 n 个 int 的连续空间
if (scores == NULL) { /* 分配可能失败，必须检查 */ }
/* ……使用这块内存，与普通数组写法完全一样…… */
free(scores);                            // 用完必须归还
```

malloc 与 free 必须**成对出现**：要了不还就是**内存泄漏**——程序每处理一个请求占一块、永不释放，内存曲线只涨不跌，长驻进程最终被系统杀死或拖垮整机。语言基础课那句「Python 不用操心内存」的底牌在这里翻开：解释器替你做 malloc/free（引用计数/垃圾回收），C 把这对权力与责任原样交到你手里。堆到底是什么、分配器怎么找空位，OS 课的「虚拟内存与内存分配」一讲会正面回答。

### 指针与数组：同一个东西的两张脸

数组名在表达式里会「退化」为指向首元素的指针——这就是为什么「数组传参会退化」（数组课的前置知识）：

```c
int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;                     // 等价于 &arr[0]

printf("%d\n", arr[2]);           // 30——下标写法
printf("%d\n", *(p + 2));         // 30——指针算术：p 往前挪 2 个 int
printf("%d\n", *(arr + 2));       // 30——arr[2] 的本质就是这个
// arr[i] 的官方定义就是 *(arr + i) —— 下标语法只是语法糖
```

**指针算术的步长由类型决定**：`p + 1` 移动的是 `sizeof(int)` 字节（4 字节），不是 1 字节——编译器根据指针类型知道「下一步跨多大」。这解释了两件事：为什么「数组长度必须传参」（sizeof 在函数内拿到的是指针大小）；为什么不同类型指针不能随意混用。

**scanf 里的 &**——语言基础课埋的伏笔在这里解开：

```c
int age;
scanf("%d", &age);      // 必须 &age：scanf 需要往「age 的房间」写入，所以要地址
// 少写 & 的后果：把 age 的「值」当地址用 → 写进随机内存 → 神秘崩溃
```

### 指针的三大应用场景（后面课程都会用到）

1. **函数改调用者的数据**（本课的 swap）——传地址而不是传值，所有「输出参数」的实现基础；
2. **遍历数组/字符串**——`char *s = "abc"; while (*s) { printf("%c", *s); s++; }`，指针沿内存前进直到 `\0`（字符串课的核心机制）；
3. **动态内存**——`malloc` 返回一块「运行时才决定大小」的内存地址，链表/树的每个节点都靠指针串起来（DSA 课的链表实现就是指针练习）。

Python/Java 不需要你操心这些，是因为它们的解释器/虚拟机内部用的就是这套机制——「引用」本质上就是包装过的指针，只是语言帮你管了分配与回收。

## 代码示例

经典 swap：错误版与正确版对照，跑一遍就懂了：

```c
#include <stdio.h>

void swap_wrong(int a, int b) {   // 拿到的是复印件
    int tmp = a; a = b; b = tmp;  // 改复印件，原件不变
}

void swap(int *a, int *b) {       // 拿到的是地址
    int tmp = *a;                 // 顺着地址取出值
    *a = *b;
    *b = tmp;
}

int main(void) {
    int x = 1, y = 2;
    swap_wrong(x, y);
    printf("wrong: x=%d y=%d\n", x, y);   // wrong: x=1 y=2（没换成！）
    swap(&x, &y);                 // 把 x、y 的地址递进去
    printf("ok:    x=%d y=%d\n", x, y);   // ok:    x=2 y=1
    return 0;
}
```

再验证一次内存图——打印地址建立直觉：

```c
int age = 18;
int *p = &age;                    // p 存下 age 的地址
printf("age=%d &age=%p p=%p *p=%d\n", age, &age, p, *p);
// age=18 &age=0x7ffd... p=0x7ffd...（相同） *p=18
*p = 20;                          // 顺着地址写入
printf("age=%d\n", age);          // age=20 —— 通过指针改动了 age 本体
```

**分支场景：malloc/free 的运行时内存**——把概念讲解的堆跑一遍：

```c
#include <stdio.h>
#include <stdlib.h>               // malloc/free 都住这个头文件

int main(void) {
    int n = 0;
    printf("要几个格子？");
    scanf("%d", &n);              // 长度运行时才知道——数组做不到，malloc 可以

    int *scores = malloc(n * sizeof(int));
    if (scores == NULL) {         // malloc 可能失败（内存不够），必须检查
        printf("内存分配失败\n");
        return 1;
    }

    for (int i = 0; i < n; i++) {
        scores[i] = i * 10;       // 用法与普通数组一模一样
    }
    printf("scores[3] = %d\n", scores[3]);   // 格子够的话：30

    free(scores);                 // 归还——malloc/free 必须成对
    scores = NULL;                // 置空，防止之后误用「悬空指针」
    return 0;
}
```

预期输出（输入 5 时）：`要几个格子？5` → `scores[3] = 30`。

输出说明了什么：n 是运行时输入的，编译期根本不知道数组该开多大——malloc 按需向堆要内存，把「大小」从编译期搬到运行期。两条纪律刻死：malloc 结果必须判 NULL；用完必须 free（不 free 就是泄漏，free 后还用就是悬空指针）。这个模型之后会长成链表（DSA）和堆分配器（OS）。

## 常见坑

1. **坑 1：解引用未初始化的指针**。`int *p; *p = 5;`——纸条上是一串垃圾地址，写入它可能让程序当场崩溃。声明时就给它地址：`int x; int *p = &x;`。
2. **坑 2：混淆 `*` 的两副面孔**。声明处 `int *p` 的 `*` 表示「p 是指针」；表达式处 `*p` 的 `*` 是解引用动作。同一符号，两种含义。
3. **坑 3：空指针不检查**。`scanf("%d", p)` 若 p 是 NULL，段错误（Segmentation fault）直接给你看。用指针前先确认它「指向一个真实存在的房间」。
4. **坑 4：swap 传成了值**。`swap(x, y)` 编译能过（类型不匹配会有警告），运行不报错但就是没效果——这是初学者最迷惑的「静默失败」。
5. **坑 5：指针算术越界**。`p + 10` 在 5 个元素的数组上「编译通过、运行随缘」——指针算术不做边界检查（呼应组成原理课的缓存越界实验），边界永远自己数。
6. **坑 6：以为指针本身有值语义**。两个指针指向同一块内存时，改 `*p1` 后 `*p2` 也变——「别名」是共享内存的自然结果，也是并发课竞态问题的微观根源。

## 小练习

1. 写一个 `void max_min(int *a, int *b)`：比较两个数，把较大者放到 a 指向的位置、较小者放到 b 指向的位置，并写 main 验证。
2. 打印 `&x`、`&x + 1`，观察两个地址差多少——这个差值和 `sizeof(int)` 有什么关系？
3. 用「纯指针写法」（不用下标）遍历一个 int 数组求和：`for (int *p = arr; p < arr + 5; p++) sum += *p;`，并与下标版对照。
4. 思考题：Python 的变量赋值 `a = b` 从不复制数据，两个名字指向同一个对象——这和 C 的指针是什么关系？
5. **综合任务**：把 malloc 版程序升级为「动态成绩单」——读入 n 与 n 个分数，求平均分后释放内存；再把 `free` 那行注释掉，用 Valgrind（Linux）或任务管理器观察「泄漏」的表现，最后补上 `scores = NULL` 前后误用 `scores[0]` 的对比实验。
