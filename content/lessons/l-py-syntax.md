> 一句话定义：Python 用**缩进**表达代码结构、用**动态类型**省掉变量声明，是反馈最快、最适合作为第一门语言学的编程语言。

## 概念讲解

### 为什么用缩进表达结构：一条高压线的由来

C 和 Java 用大括号 `{}` 划定代码块，Python 把大括号扔了，**缩进本身就是语法**。这不是审美偏好，而是精明的设计取舍。用盖楼打比方：

```python
# C 语言：结构靠大括号，缩进只是给人看的礼貌——缩进骗人，编译器不吭声
if (score >= 90) { printf("A"); }
# Python：缩进就是结构本身——缩进错了，程序根本跑不起来
if score >= 90:
    print("A")
```

C 的坑在于「人眼看到的」和「机器执行的」可以不一致，bug 躲在缝隙里；Python 干脆让两者**强制合一**，错误在第一时间暴露。纪律只有一条：同一层级缩进完全一致，用 4 个空格（编辑器按 Tab 自动给 4 空格）。冒号 `:` 是块开始的信号——见到冒号，下一行必然缩进。

### 变量与动态类型：变量是标签，不是盒子

大多数语言声明变量要先报类型（`int age = 18;`），Python 直接赋值：`name = "小明"`、`age = 18`。理解差别要把变量想成**标签**而不是**盒子**：盒子模型（C）里容器造好就固定形状，只能装 int；标签模型（Python）里 `age = 18` 是把写着 `age` 的标签贴到内存中的数据 `18` 上，数据自带类型，标签只是名字。所以同一个名字随时可以贴到别的数据上：

```python
x = 18
print(type(x))   # <class 'int'>
x = "十八"
print(type(x))   # <class 'str'>   同一个标签，贴到了字符串上
```

`type()` 是自查工具：拿不准变量现在是什么，打印一眼便知。动态类型的代价是**类型错误推迟到运行时才爆**——`age + "岁"` 在 C 里编译不过，在 Python 里要跑到那一行才崩，所以「写完立刻跑一遍」是 Python 的工作节奏。

### 数字与运算：/、//、%、** 四件套辨析

三个除法符号最容易混，一张表分清，这张表值得背下来：

| 运算符 | 名字 | 示例 | 结果 | 关键记忆点 |
| ---- | ---- | ---- | ---- | ---- |
| `/` | 真除法 | `10 / 4` | `2.5` | **永远返回 float**，`8 / 2` 也是 `4.0` |
| `//` | 整除（向下取整） | `10 // 4` | `2` | 舍掉小数，返回 int；`-7 // 2` 得 `-4`（向负无穷取整） |
| `%` | 求余（取模） | `10 % 4` | `2` | 判奇偶、分组轮转全靠它：`n % 2 == 0` 即偶数 |
| `**` | 幂运算 | `2 ** 10` | `1024` | 开平方可写 `16 ** 0.5` |

最大误区是把 `/` 当成 C 的整数除法——Python 的 `/` 只要参与运算，结果必是浮点数。常用数学函数不必自己写：`import math` 后 `math.sqrt(16)` 得平方根 `4.0`、`math.floor(3.7)` 向下取整得 3；四舍五入用内置的 `round(3.14159, 2)` 得 3.14，连 import 都不用。

### 控制流：三大武器全解

**if / elif / else**——冒号加缩进，`elif` 是 "else if" 的缩写，按顺序检查、命中即停：

```python
score = 85
if score >= 90:
    print("优秀")
elif score >= 60:
    print("及格")     # 85 走到这一支
else:
    print("不及格")
```

**for 循环 + range**——Python 的 for 是「遍历」语义，直接迭代序列的每个元素，不需要 C 那种 `for (i=0; i<n; i++)` 计数器写法；要计数器时用 `range()`，三种用法必须记牢：

| 写法 | 生成的序列 | 典型用途 |
| ---- | ---- | ---- |
| `range(5)` | 0, 1, 2, 3, 4 | 循环 n 次（**含头不含尾**） |
| `range(2, 6)` | 2, 3, 4, 5 | 指定起点（同样含头不含尾） |
| `range(0, 10, 2)` | 0, 2, 4, 6, 8 | 步长 2，隔项处理 |

`range(5)` 不含 5，正如切片 `[0:5]` 不含下标 5——Python 全家统一「含头不含尾」，要包含 N 就写 `range(N + 1)`。需要下标时用 `range(len(scores))`，但更 Python 的写法是直接 `for score in scores`，要下标才退而求其次。

**while + break / continue**——不知道循环几次、只知道循环条件时用 while。`break` 跳出整个循环，`continue` 跳过本轮剩余语句直接进入下一轮：

```python
count = 3
while count > 0:
    count -= 1
    if count == 1:
        continue      # 跳过下面的 print，回到 while 条件判断
    print(count)      # 依次打印 2
```

`while True` + `break` 是「菜单循环」的标准套路（程序一直运行直到用户选退出），后面讲文件与异常时会用到。另外 Python 3.10 起有 `match` 结构化分支（类似其他语言的 switch），入门阶段知道它存在即可，本项目用不上。

### 函数：把一段逻辑装进命名的盒子

```python
def average(numbers):
    """计算平均值；空列表返回 0 而不是报错"""
    if not numbers:
        return 0                       # 提前出口
    return sum(numbers) / len(numbers) # 返回值交还调用者

print(average([92, 88, 75]))   # 85.0
```

拆解五个零件：`def` 开启定义；`average` 是函数名（起名像动词短语）；`(numbers)` 是**参数**——函数的输入口，调用时传入的 `[92, 88, 75]` 叫**实参**；三引号字符串是**文档字符串（docstring）**，函数的说明书；`return` 把结果交还调用者。两个关键细节：`return` 之后函数立刻结束，所以它兼具「提前出口」功能（上面用它拦截空列表）；**没写 return 的函数返回 `None`**——「什么都不返回」也是一种返回值，调试时会反复遇到。函数还能一次返回多个值（本质打包成元组，接收时解包）：

```python
def min_max(numbers):
    return min(numbers), max(numbers)

low, high = min_max([92, 88, 75])   # 解包：low=75, high=92
```

### f-string：现代 Python 的字符串格式化标准

字符串前加 `f`，花括号里直接嵌变量、甚至就地写表达式；`:.1f` 表示保留 1 位小数（格式说明符的进阶玩法在字符串课展开）：

```python
name, score = "小明", 92
print(f"{name} 考了 {score} 分")          # 小明 考了 92 分
print(f"平均 {sum([92, 88]) / 2:.1f}")    # 平均 90.0
```

从现在起拼接字符串一律用 f-string——`+` 号拼接数字要先转 str，又丑又容易错。

## 代码示例

主线任务：**从需求推导出完整的「成绩统计器」**，走一遍真实开发流程：需求 → 拆解 → 逐步实现 → 每步运行验证，跟着做约 25 分钟。

### 第 0 步：明确需求，拆解成三块

需求一句话：「有一批学生成绩，输出带等级评定的统计报表」。程序员第一个动作永远是**拆**——混在一起写，出一半错都不知道错在哪一层，拆成子问题才能逐块验证：

```text
成绩统计器
├── 1. 判定：单个分数 → 等级（A/B/C/F）
├── 2. 统计：一批分数 → 平均分、最高分、及格率
└── 3. 输出：逐个打印「姓名 分数 等级」，最后打印统计行
```

### 第 1 步：先解决「判定」

新建文件 `grade.py`，写判定逻辑（一个函数 + 一次手动验证）：

```python
def grade(score):
    """百分制分数 → 等级：90 以上 A，80 以上 B，60 以上 C，否则 F"""
    if score >= 90:
        return "A"
    elif score >= 80:
        return "B"
    elif score >= 60:
        return "C"
    else:
        return "F"

print(grade(92), grade(80), grade(59))    # A B F —— 80 正好压在分界线上
```

运行 `python grade.py`，输出 `A B F`。为什么先测边界值：分界线（90、80、60）是 bug 高发区，`>= 90` 还是 `> 90` 只有拿 90 本身来测才知道；`grade(80)` 得 B，证明边界归入更大的一档。

### 第 2 步：加上数据，逐个处理

真实数据「姓名 + 分数」成对出现，用列表套元组表示（容器细节下一课展开，先照抄）：

```python
students = [("小明", 92), ("小红", 75), ("小刚", 58), ("小丽", 80)]
for name, score in students:
    print(f"{name}: {score} 分 → {grade(score)}")
```

运行结果：

```text
小明: 92 分 → A
小红: 75 分 → C
小刚: 58 分 → F
小丽: 80 分 → B
```

`for name, score in students` 是**元组解包**——每个元素是二元组，循环时直接拆成两个变量，免去 `s[0]`、`s[1]` 的下标地狱；`grade(score)` 放进 f-string 就地调用，一行完成「取值、判定、拼接」。

### 第 3 步：补上统计行

加平均分、最高分与及格率。及格判定复用 `grade` 的思路——已写过的逻辑不重抄：

```python
scores = [s for _, s in students]      # 从 (姓名, 分数) 列表抽出分数列
avg = sum(scores) / len(scores)
passed = sum(1 for _, s in students if s >= 60)
rate = passed / len(students) * 100
print("-" * 30)
print(f"平均分: {avg:.1f}  最高分: {max(scores)}")
print(f"及格率: {rate:.0f}%")
```

运行结果：

```text
------------------------------
平均分: 76.2  最高分: 92
及格率: 75%
```

`[s for _, s in students]` 是**列表推导式**，下划线 `_` 是约定的「这个值我不要」占位名；`sum(1 for ... if 条件)` 数出满足条件的个数，比循环计数器短得多；`"-" * 30` 是字符串乘法画分隔线。

### 第 4 步：组装成完整程序

把三步合成最终版本（完整代码，可直接复制运行）：

```python
def grade(score):
    """百分制分数 → 等级"""
    if score >= 90:
        return "A"
    elif score >= 80:
        return "B"
    elif score >= 60:
        return "C"
    else:
        return "F"

students = [("小明", 92), ("小红", 75), ("小刚", 58), ("小丽", 80)]
print("=== 成绩统计报表 ===")
for name, score in students:
    print(f"{name}: {score} 分 → {grade(score)}")

scores = [s for _, s in students]
avg = sum(scores) / len(scores)
passed = sum(1 for _, s in students if s >= 60)
rate = passed / len(students) * 100
print("-" * 30)
print(f"平均分: {avg:.1f}  最高分: {max(scores)}")
print(f"及格率: {rate:.0f}%")
```

运行结果：

```text
=== 成绩统计报表 ===
小明: 92 分 → A
小红: 75 分 → C
小刚: 58 分 → F
小丽: 80 分 → B
------------------------------
平均分: 76.2  最高分: 92
及格率: 75%
```

对照第 0 步的拆解图验收：判定（grade 函数）、统计（三行计算）、输出（两段打印）全部落地。程序约 30 行，但走完了「需求→拆解→实现→验证」全流程——字符串课会给它更复杂的数据处理，函数课会把它重构成真正的函数版。

## 常见坑

1. **坑 1：缩进混用空格与 Tab**。现象：`IndentationError: unindent does not match any outer indentation level`，或报错在毫不相干的行。原因：空格和 Tab 视觉相同、字节不同，Python 按缩进字符判层级，混用即失败。排查：VS Code 用「渲染空白字符」功能让 Tab 原形毕露，统一设为 4 空格。
2. **坑 2：`=` 与 `==` 用反**。现象：`if x = 5:` 直接 `SyntaxError`。原因：`=` 是赋值、`==` 才是比较，Python 禁止在条件里赋值（比 C 严格，反而是保护）。排查：报错行号直指问题行，改符号即可。
3. **坑 3：把 `/` 当整除用**。现象：`8 / 2` 得 `4.0`，后续逻辑偏差或打印难看。原因：`/` 永远返回浮点数。对策：要整数结果写 `//`，要四舍五入写 `round()`，展示格式交给 f-string。
4. **坑 4：range 忘了「含头不含尾」**。现象：想循环 n 次却少一次，或 `range(1, 5)` 以为包含 5。原因：range 与切片统一含头不含尾。对策：默念口诀，要包含 N 就写 `range(N + 1)`。
5. **坑 5：float 精度惊魂**。现象：`print(0.1 + 0.2)` 得 `0.30000000000000004`。原因：二进制浮点无法精确表示 0.1，所有语言皆然，不是 bug。对策：比较前 `round()`；金额用整数「分」做单位。
6. **坑 6：在 for 遍历中增删列表元素**。现象：遍历中 append/remove 后元素被跳过或重复处理，结果时对时错。原因：遍历器按位置前进，长度中途变化导致错位。对策：遍历副本 `for s in students[:]`，或遍历完用推导式重建。

2. 用嵌套 for 打印九九乘法表前三行（`1×1=1` 到 `3×3=9`），内层 range 的上限要跟着外层变量走。
