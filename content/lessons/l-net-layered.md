> 一句话定义：分层 = 把「从敲下回车到看到网页」这件事拆成几段，每段只解决一个问题，段与段之间靠约定（协议）衔接。

## 概念讲解

为什么一定要分层？因为整个链路太复杂：要选路、要纠错、要编码、要渲染……不分层的话，任何一个改动都要重新理解全局。分层的本质是**关注点分离**——和编程里的「模块化」完全同构。

面试常背 OSI 七层，实际工作用 **TCP/IP 四层**就够了：

| TCP/IP 层 | 干什么 | 代表协议 | 一个类比（寄快递） |
| ---- | ---- | ---- | ---- |
| 应用层 | 解决「发什么内容」 | HTTP、DNS、WebSocket | 你写的信的内容 |
| 传输层 | 解决「发给谁、丢不丢」 | TCP、UDP | 快递单：地址 + 保价 |
| 网络层 | 解决「怎么走到那」 | IP、ICMP | 干线运输路线 |
| 网络接口层 | 解决「最后一公里」 | 以太网、Wi-Fi | 配送员骑车上门 |

发送方逐层**封装**：应用层的数据，交给传输层时会加上 TCP 头，再交给网络层加 IP 头……像信装进信封、信封装进包裹。接收方逐层**解封装**，每层撕掉自己的那层「包装纸」。

**分层给排错的礼物**：一套从下到上的排查顺序——网线/Wi-Fi 通不通（接口层）→ 能不能 ping 通目标 IP（网络层）→ 端口通不通（传输层）→ 服务返回什么（应用层）。有层次的地图，让「断网了」不再是玄学。

## 代码示例

用一条命令直观看到「每层各管一段」：

```bash
# 网络层：能不能到达目标主机（ICMP）
ping www.baidu.com

# 传输层：目标主机的 443 端口通不通
curl -v telnet://www.baidu.com:443

# 应用层：HTTP 服务到底返回什么
curl -sI https://www.baidu.com
```

三层命令全绿，才是「网络没问题」的完整定义。面试题「网页打不开怎么排查」，标准答案就是沿这个顺序逐层收窄。

## 常见坑

1. **坑 1：死背七层却说不清每层解决什么问题**。背层数没意义，背「每层的职责一句话」才有用——面试官问的是理解，不是朗诵。
2. **坑 2：把「能 ping 通」当成「网络没问题」**。ping 只证明网络层通，443 端口被防火墙挡住时页面照样打不开。排查：补一条 `curl -v telnet://目标:端口`。
3. **坑 3：以为分层是物理上的分开**。四层都在同一台机器、同一块网卡上跑，分层是**逻辑**上的分工，靠数据封装衔接。

## 小练习

1. 对任意网站依次跑上面三条命令，把每层的结果记录下来（通了/不通）。
2. 用类比法向朋友解释：为什么 IP 层的地址和 MAC 地址要同时存在？
3. 思考题：为什么「保证不丢包」放在传输层（TCP），而不是网络层（IP）？
