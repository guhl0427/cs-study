## 1. 项目概述

### 1.1 项目背景

计算机科学技术方向的学生和初学者普遍面临以下痛点：

1. **不知道学什么**：技术栈庞杂（前端、后端、数据库、AI……），入门者缺乏全局视野，容易迷茫。
2. **不知道按什么顺序学**：网络上的资料碎片化，缺乏清晰的先后依赖关系，容易「东一榔头西一棒子」。
3. **不知道学到什么程度**：教程质量参差不齐，初学者难以判断内容的深度与时效性。
4. **学了就忘、难以坚持**：缺乏进度记录与正向反馈，学习动力难以维持。

现有产品各有侧重（路线图类如 roadmap.sh 偏导航、教程类网站偏工具书、视频平台偏课程），但缺少一个「**领域导航 + 学习路线 + 结构化内容 + 进度跟踪**」一体化的中文学习平台。

### 1.2 产品定位

面向**计算机专业学生与初学者**的结构化学习平台：以「技术领域 → 学习路线 → 课程内容 → 进度反馈」为主线，帮助学习者**一进来就能找到自己能学的领域**，并沿着清晰的路线持续学习。

一句话描述：**为 CS 初学者提供一张清晰的「学习地图」，并陪他走完全程。**

### 1.3 产品目标

| 目标 | 衡量标准 |
| ---- | ---- |
| 让初学者 3 分钟内找到适合的学习方向 | 新访客进入首页 → 选定领域/路线的转化率 |
| 提供体系化、可执行的学习路线 | 每个领域均有完整路线图（阶段 + 知识点 + 依赖关系） |
| 提供高质量结构化内容 | 每个知识点均有原创讲解 + 精选外链资源 |
| 建立学习闭环 | 学习进度记录、测验反馈、打卡激励，提升留存与完课率 |

### 1.4 价值主张（与现有产品的差异化）

| 维度 | 本平台 | roadmap.sh 类 | 教程网站类 | 视频课程类 |
| ---- | ---- | ---- | ---- | ---- |
| 领域全景导航 | ✅ | ✅ | ❌ | ❌ |
| 结构化站内内容 | ✅ | ❌ | ✅ | ✅ |
| 学习路线与依赖关系 | ✅ | ✅ | 部分 | ❌ |
| 进度跟踪与打卡 | ✅ | 部分 | ❌ | 部分 |
| 中文原生内容 | ✅ | ❌（英文为主） | ✅ | ✅ |
| 精选外链资源整合 | ✅ | 部分 | ❌ | ❌ |

### 1.5 成功指标（初期参考）

- 新访客 3 分钟内进入某个领域/路线页面的比例 ≥ 40%
- 注册用户周留存 ≥ 25%
- 「继续学习」功能使用率（注册用户）≥ 50%
- 核心课程完课率 ≥ 30%

## 2. 目标用户与角色

### 2.1 用户画像

| 画像 | 描述 | 核心诉求 |
| ---- | ---- | ---- |
| **在校 CS 学生**（大一~大三） | 已修/正在修专业课程（C 语言、数据结构等），想补齐工程实践方向（前端/后端/数据库），为实习、校招做准备 | 清晰的就业方向路线图、与校招要求对齐的知识清单、项目实战指引 |
| **转行初学者** | 非计算机专业出身，自学转行，基础薄弱 | 从零开始的平滑路径、明确「先学什么后学什么」、避免被进阶内容劝退 |
| **自学进阶者** | 已掌握一门语言/一个方向，想扩展技术面（如后端学 AI、前端学 Node.js） | 按需检索知识点、进阶内容与优质外链资源 |

### 2.2 系统角色与权限

| 角色 | 权限说明 |
| ---- | ---- |
| **游客** | 浏览全部公开内容（领域、路线图、课程、知识点）；搜索；**无进度记录、无测验作答记录**（可试用不落库） |
| **学员**（注册用户） | 游客全部能力 + 学习进度记录、打卡、测验作答与错题本、收藏、纠错反馈、个人中心 |
| **内容创作者** | 登录后台，管理被授权领域下的课程/章节/知识点/外链资源/题目；提交内容审核（草稿 → 发布） |
| **管理员** | 全部后台权限：内容审核与发布、领域与路线图管理、用户管理（封禁/角色分配）、数据统计 |

## 3. 技术领域与内容体系

> 本章是平台的内容骨架，直接决定「一进来就能找到能学的领域」能否成立。

### 3.1 设计原则

1. **领域即入口**：首页按领域组织，每个领域是一张独立的「学习地图」。
2. **难度统一分级**：所有知识点、课程、路线阶段统一使用四级难度体系。
3. **原创骨架 + 精选外链**：每个知识点由站内原创讲解（概念、示例、避坑）构成骨架，并挂载经过筛选的优质外部资源（官方文档、经典书籍、公开课）作为延伸。
4. **依赖关系显式化**：知识点之间的前置关系在路线图中显式标注，杜绝「还没学走就想跑」。

**难度分级体系（全站统一）：**

| 等级 | 名称 | 描述 |
| ---- | ---- | ---- |
| L1 | 入门 | 零基础可学，掌握概念与基本使用 |
| L2 | 基础 | 能独立完成简单任务，理解常用特性 |
| L3 | 进阶 | 理解原理，能解决较复杂问题 |
| L4 | 精通 | 深入底层与最佳实践，能指导他人 |

### 3.2 领域总览

| # | 领域 | 定位 | 建议先修 | 难度跨度 |
| ---- | ---- | ---- | ---- | ---- |
| ① | 计算机基础 | 全领域的地基，CS 学生必修 | 无 | L1–L3 |
| ② | 编程语言 | 第一门语言的起点 | 计算机基础（可并行） | L1–L4 |
| ③ | 前端开发 | 就业主流方向之一 | ② 中的 JavaScript/TypeScript | L1–L4 |
| ④ | 后端开发 | 就业主流方向之一 | ② 中的一门语言 + ① | L1–L4 |
| ⑤ | 数据库 | 后端必配，独立技能 | ④（可并行） | L1–L3 |
| ⑥ | 开发工具与环境 | 全领域通用生产力 | 无 | L1–L2 |
| ⑦ | 软件工程 | 从「会写代码」到「会做工程」 | ⑥ Git | L1–L3 |
| ⑧ | AI 与数据 | 新兴热点方向 | ② Python + ① 基础 | L2–L4 |
| ⑨ | 选修拓展 | 安全、移动端等兴趣方向 | 视子方向而定 | L2–L4 |

**典型学习起点推荐（用于首页引导）：**

- 完全零基础 → ⑥ Git/IDE → ② C 或 Python 入门 → ① 计算机基础（并行）→ 选定方向（③/④）
- 在校 CS 学生 → ① 计算机基础查漏 → ④ 后端 或 ③ 前端 → ⑤ 数据库 → ⑦ 软件工程 → 项目实战
- 转行求快 → ② Python → ④ 后端（Python/FastAPI 路线）→ ⑤ SQL → ⑥ Git/Docker

### 3.3 各领域详细说明

#### ① 计算机基础

**简介**：计算机科学与技术的地基，决定学习者后续天花板。与校内课程对应，可辅助专业课学习。

**适合人群**：所有初学者（尤其是 CS 在校生）；建议与前端/后端方向并行学习。

**前置知识**：无。

**技术清单：**

| 技术点 | 内容范围 | 难度 | 建议时长 |
| ---- | ---- | ---- | ---- |
| 数据结构与算法 | 线性表、栈与队列、哈希表、树、堆、图、排序与查找、递归、动态规划入门 | L1–L3 | 8–12 周 |
| 计算机网络 | 网络分层模型（OSI/TCP-IP）、HTTP/HTTPS、TCP/UDP、DNS、抓包初步 | L1–L3 | 4–6 周 |
| 操作系统 | 进程与线程、内存管理、文件系统、I/O 与中断 | L2–L4 | 6–8 周 |
| 计算机组成原理 | 进制与编码、CPU 与指令、存储层次结构 | L2–L3 | 4–6 周 |

**精选外链类型**：《图解 HTTP》《计算机网络：自顶向下方法》《操作系统导论》《深入理解计算机系统（CSAPP）》；LeetCode / 洛谷刷题平台；相关公开课。

**学习阶段**：S1 数据结构与算法 + 网络基础 → S2 操作系统 + 组成原理 → S3 结合后端方向综合应用。

#### ② 编程语言

**简介**：第一门编程语言的起点与多语言拓展。原则：**主修 1 门 + 辅修 1 门**，忌贪多。

**适合人群**：零基础新手（从 C 或 Python 起步）、需第二门语言的进阶者。

**前置知识**：计算机基础（可并行）。

**技术清单：**

| 语言 | 定位 | 难度 | 建议时长 | 说明 |
| ---- | ---- | ---- | ---- | ---- |
| Python | 首选通用入门；数据/AI 方向基础 | L1–L2 | 3–4 周 | 语法友好，反馈快 |
| C | 理解内存、指针与底层机制 | L2–L3 | 4–6 周 | 与《组成原理》联动，CS 学生建议接触 |
| Java | 后端就业主流语言 | L1–L3 | 8–12 周 | 面向对象 + 生态庞大 |
| Go | 后端/云原生方向，语法精简 | L1–L2 | 3–4 周 | 上手快，部署简单 |
| JavaScript | Web 前端核心语言 | L1–L3 | 4–6 周 | 归入前端路线亦可 |
| TypeScript | JS + 类型系统 | L2–L3 | 2–3 周 | 前端框架必备 |
| C++ | 系统级/高性能/竞赛 | L3–L4 | 12 周+ | 选修 |
| Rust | 内存安全的新兴系统语言 | L3–L4 | 选修 | 兴趣驱动 |

**学习阶段**：S1 第一门语言（Python 或 C）→ S2 方向语言（Java / Go / JS+TS）→ S3 第二语言与范式拓展（选修）。

#### ③ 前端开发

**简介**：从页面三件套到框架与工程化的完整前端路线。

**适合人群**：喜欢可视化反馈、面向 Web 开发就业的学习者。

**前置知识**：JavaScript / TypeScript（可在本路线内学习）。

**技术清单：**

| 技术点 | 内容范围 | 难度 | 建议时长 |
| ---- | ---- | ---- | ---- |
| HTML5 | 语义化标签、表单、多媒体、可访问性初步 | L1 | 1–2 周 |
| CSS3 | 盒模型、选择器、Flex/Grid 布局、定位、动画过渡 | L1–L2 | 2–3 周 |
| JavaScript (ES6+) | 基础语法、DOM 与事件、异步编程（Promise/async）、模块化 | L1–L3 | 4–6 周 |
| CSS 进阶 | 响应式设计、Sass/Less、Tailwind CSS | L2 | 1–2 周 |
| TypeScript | 类型系统、泛型、配置与工程接入 | L2–L3 | 2–3 周 |
| Vue 3 生态 | Vue 3 组合式 API、Vue Router、Pinia、Element Plus / Naive UI | L2–L3 | 4–6 周 |
| React 生态 | React 18 Hooks、React Router、Redux Toolkit / Zustand、Ant Design | L2–L3 | 4–6 周 |
| 工程化 | Node.js 与 npm/pnpm 基础、Vite、ESLint/Prettier、环境变量 | L2 | 2 周 |
| 浏览器原理与性能优化（进阶） | 渲染流程、事件循环、跨域、打包优化、懒加载 | L3–L4 | 2–3 周 |
| SSR / 元框架（进阶选修） | Nuxt / Next.js | L3–L4 | 选修 |

**说明**：Vue 与 React **二选一深入**（另一门了解即可），路线图中作为并列分支呈现。

**学习阶段**：S1 HTML/CSS/JS 三件套 → S2 TypeScript + 框架（Vue 或 React）→ S3 生态与工程化 → S4 原理、性能与 SSR（进阶）。

#### ④ 后端开发

**简介**：以「语言 + Web 框架 + 数据存储 + 中间件」为主线的服务端开发路线，含 Java、Go、Python 三条语言分支。

**适合人群**：对系统逻辑、数据流转感兴趣，面向服务端开发就业的学习者。

**前置知识**：一门编程语言（②）、计算机网络与 SQL 基础（①⑤可并行）。

**技术清单：**

| 技术点 | 内容范围 | 难度 | 建议时长 |
| ---- | ---- | ---- | ---- |
| Web 通用基础 | HTTP 深入、RESTful API 设计、JSON、Cookie/Session、JWT/OAuth2 认证授权 | L1–L3 | 2–3 周 |
| Java 方向 | Java SE → Maven/Gradle → Spring Boot → Spring MVC → MyBatis-Plus / Spring Data JPA → Spring Security →（进阶）JVM 与调优 | L1–L4 | 10–14 周 |
| Go 方向 | Go 语法 → go mod → Gin → GORM →（进阶）gRPC、并发模型 | L1–L3 | 6–8 周 |
| Python 方向 | Flask / Django / FastAPI 三框架概览 + 一框架深入 | L1–L3 | 4–8 周 |
| 缓存 | Redis 数据类型、缓存穿透/击穿/雪崩、持久化 | L2–L3 | 1–2 周 |
| 消息队列 | RabbitMQ / Kafka 基本使用与典型场景（异步、解耦、削峰） | L2–L3 | 1–2 周 |
| 搜索（选修） | Elasticsearch 基础使用 | L3 | 选修 |
| 微服务与分布式（进阶选修） | 服务注册发现、网关、分布式事务、Spring Cloud | L3–L4 | 选修 |

**学习阶段**：S1 语言巩固 + Web 基础 → S2 Web 框架入门（CRUD 项目）→ S3 数据库 + 缓存整合 → S4 认证、测试、部署的完整项目实战 → S5 微服务/分布式（选修）。

#### ⑤ 数据库

**简介**：从 SQL 语言到数据库设计与优化，覆盖关系型、缓存型、文档型三类存储。

**适合人群**：所有后端学习者（必修）；数据方向学习者。

**前置知识**：无硬性前置（与后端方向并行最佳）。

**技术清单：**

| 技术点 | 内容范围 | 难度 | 建议时长 |
| ---- | ---- | ---- | ---- |
| SQL 语言 | DDL/DML/DQL、多表联查（JOIN）、聚合与分组、子查询、窗口函数初步 | L1–L2 | 2–3 周 |
| MySQL | 安装与配置、存储引擎、索引原理、事务与隔离级别、SQL 优化（EXPLAIN） | L1–L3 | 4–5 周 |
| PostgreSQL | 与 MySQL 对照学习、JSONB、数组类型、CTE、全文检索初步 | L2–L3 | 3–4 周 |
| 数据库设计 | ER 建模、三大范式、反范式权衡、库表设计实践 | L2–L3 | 2 周 |
| Redis | 数据类型与场景、缓存策略、主从与持久化概念 | L2–L3 | 1–2 周 |
| MongoDB（选修） | 文档模型、聚合管道、适用场景 | L2–L3 | 选修 |
| ORM | MyBatis / JPA（Java）、GORM（Go）、SQLAlchemy（Python） | L2 | 1 周 |
| 分库分表与高可用（进阶选修） | 读写分离、分区、分库分表 | L4 | 选修 |

**说明**：MySQL 与 PostgreSQL 的 SQL 语言高度共通，课程内容以「一套 SQL + 两个数据库的对照差异」组织，既满足两者学习目标，又避免重复学习。

**学习阶段**：S1 SQL 语言 → S2 深入一个关系型库（MySQL 或 PostgreSQL）→ S3 设计与优化 → S4 Redis 与 NoSQL → S5 分库分表（选修）。

#### ⑥ 开发工具与环境

**简介**：全方向通用的生产力基础设施，建议在第一周就学 Git 与 IDE 基础。

**适合人群**：所有学习者。

**前置知识**：无。

**技术清单：**

| 技术点 | 内容范围 | 难度 | 建议时长 |
| ---- | ---- | ---- | ---- |
| Git / GitHub | 初始化与提交、分支与合并、远程协作、Pull Request、解决冲突 | L1–L2 | 1 周 |
| IDE 与编辑器 | VS Code / IntelliJ IDEA 高效使用、常用插件、调试技巧 | L1 | 0.5 周 |
| Linux 与 Shell | 常用命令、文件权限、vim 基础、Shell 脚本入门、SSH | L1–L2 | 2 周 |
| Docker | 镜像与容器、Dockerfile、docker-compose、部署实践 | L2 | 1–2 周 |
| 包管理 | npm/pnpm、Maven、go mod、pip 概念对照 | L1 | 0.5 周 |
| 效率工具 | Markdown、正则表达式基础、AI 辅助编码工具的正确使用 | L1 | 0.5 周 |

**学习阶段**：S1 Git + IDE（随第一门语言同步）→ S2 Linux 与 Shell → S3 Docker → S4 与 CI/CD 实践联动（见 ⑦）。

#### ⑦ 软件工程

**简介**：从「会写代码」到「会做工程」的桥梁，以项目实战为载体穿插学习。

**适合人群**：完成一门语言入门、准备做项目的学习者；求职冲刺期学生。

**前置知识**：Git（⑥）、一门语言基础（②）。

**技术清单：**

| 技术点 | 内容范围 | 难度 | 建议时长 |
| ---- | ---- | ---- | ---- |
| 单元测试 | 概念与测试金字塔、JUnit（Java）/ pytest（Python）/ Jest（前端） | L2 | 1 周 |
| 接口调试 | Postman / Apifox / curl、接口文档（OpenAPI 概念） | L1–L2 | 0.5 周 |
| 代码规范 | 命名、注释、格式化工具（Checkstyle / ESLint / gofmt）、重构初步 | L1–L2 | 1 周 |
| 协作流程 | 分支策略（Git Flow / 主干开发）、Code Review 流程、issue 管理 | L2 | 1 周 |
| CI/CD | GitHub Actions 入门：自动测试、自动构建与部署 | L2–L3 | 1 周 |
| 需求与敏捷（了解） | 用户故事、迭代、看板方法 | L1 | 0.5 周 |

**学习阶段**：本领域不以线性阶段推进，而是作为「项目实战配套」分散嵌入各方向路线的项目阶段。

#### ⑧ AI 与数据

**简介**：面向未来就业趋势的新兴方向，从数据分析到大模型应用开发。

**适合人群**：已掌握 Python 基础的学习者；对 AI 应用开发感兴趣者。

**前置知识**：Python（②）、数据结构与算法基础（①）、概率统计初步。

**技术清单：**

| 技术点 | 内容范围 | 难度 | 建议时长 |
| ---- | ---- | ---- | ---- |
| Python 数据基础 | NumPy、pandas、Matplotlib 数据清洗与可视化 | L2 | 2–3 周 |
| 机器学习入门 | 监督/无监督概念、线性回归、决策树、KNN、scikit-learn 实践、模型评估 | L2–L3 | 4–6 周 |
| 深度学习概览（选修） | 神经网络概念、PyTorch 入门、经典网络一览 | L3–L4 | 选修 |
| 大模型应用开发 | Prompt 工程方法、调用 LLM API、RAG 检索增强概念、LangChain 入门 | L2–L3 | 3–4 周 |
| 数据分析实战（选修） | 真实数据集分析项目、SQL + pandas 组合 | L2–L3 | 选修 |

**学习阶段**：S1 Python + 数据分析 → S2 机器学习入门 → S3 大模型应用开发 → S4 深度学习（选修）。

#### ⑨ 选修拓展

**简介**：兴趣与就业加分项，以概览 + 单点深入的方式组织。

| 子方向 | 内容范围 | 难度 |
| ---- | ---- | ---- |
| Web 安全 | 常见漏洞与防御（XSS、CSRF、SQL 注入）、HTTPS 原理、密码存储（哈希加盐）、鉴权安全 | L2–L3 |

| 桌面开发（了解） | Electron / Tauri 概览 | L2 |

### 3.4 内容生产规范

为保证内容质量与一致性，每个知识点页面遵循统一模板：

1. **一句话定义**：这是什么、解决什么问题。
2. **概念讲解**：配图 / 类比，控制在初学者可读的篇幅。
3. **代码示例**：可运行、带注释，附运行结果。
4. **常见坑**：初学者高频错误与排查思路。
5. **小练习**：1–3 道自测题（衔接 F5 测验模块）。
6. **精选外链**：官方文档 / 书籍章节 / 公开课，标注类型、难度、推荐理由。

## 6. 技术架构与选型建议

### 6.1 总体架构

```
                    ┌─────────────────────────────┐
                    │          用户 / 管理员        │
                    └──────────┬──────────────────┘
                               │ HTTPS
                    ┌──────────▼──────────────────┐
                    │            Nginx             │
                    │   静态资源 / 反向代理 / TLS    │
                    └──────┬──────────────┬───────┘
                           │              │
              ┌────────────▼───┐   ┌──────▼─────────────┐
              │  前台 SPA (Vue) │   │  后台管理 SPA (Vue) │
              └────────────┬───┘   └──────┬─────────────┘
                           │   REST/JSON  │
                    ┌──────▼──────────────▼───────┐
                    │        后端 API 服务          │
                    │  (Spring Boot，备选 Gin/Go)   │
                    └──────┬──────────────┬───────┘
                           │              │
                  ┌────────▼─────┐  ┌─────▼──────┐
                  │ PostgreSQL   │  │   Redis    │
                  │  主数据存储    │  │ 缓存/会话   │
                  └──────────────┘  └────────────┘
```

- 前台与后台均为独立 SPA，共用一套后端 API。
- 内容（Markdown 文本）存储在数据库中，由后端渲染接口输出（前台负责展示层渲染与代码高亮）。
- SEO 关键页面（课程/知识点详情）采用预渲染或 SSR 增强（见 6.2）。

### 6.2 前端选型

| 项 | 选型 | 说明 |
| ---- | ---- | ---- |
| 框架 | **Vue 3 + TypeScript** | 组合式 API 生态成熟，国内资料丰富 |
| 构建 | Vite | 开发热更新快，构建简单 |
| 状态管理 | Pinia | Vue 官方推荐 |
| 路由 | Vue Router 4 | — |
| UI 组件 | 前台：Naive UI / 自建设计系统；后台：Element Plus | 后台优先开发效率 |
| 样式 | Tailwind CSS（前台可选） | 快速实现响应式布局 |
| Markdown 渲染 | markdown-it + Shiki（或 highlight.js） | 代码高亮质量好 |
| SEO | 预渲染（vite-prerender 类方案）或升级 Nuxt 3 | MVP 可先 SPA + 预渲染，流量增长后评估 Nuxt |

### 6.3 后端选型：Java (Spring Boot) vs Go (Gin)

| 维度 | Java（Spring Boot 3.x） | Go（Gin） |
| ---- | ---- | ---- |
| 学习曲线 | 较陡（概念多：注解、IoC、AOP），但体系成熟 | 语法精简，上手快 |
| 生态与中间件 | 极其丰富（Spring 全家桶覆盖安全、ORM、微服务） | 精炼够用，部分场景需自组装 |
| 中文资料与教程 | 最丰富，校招面试主线技术栈 | 快速增长，云原生方向强势 |
| 开发效率 | 中（模板代码偏多） | 高（代码量少，编译快） |
| 运行性能/资源 | 中等（JVM 内存占用较高） | 高并发场景优，资源占用低 |
| 部署 | JAR + JVM，镜像较大 | 单二进制，镜像极小 |
| 与本平台内容的契合 | 平台自身代码可直接作为「Java 后端路线」的实战范本 | 平台代码可作为「Go 路线」参考项目 |

**推荐：Spring Boot 3.x + Java 17/21（主选）。**

理由：

1. 平台目标用户是国内 CS 学生，**Spring Boot 是校招与就业市场的主流技术栈**，平台自身的源码即可成为「后端方向」课程的真实案例，实现「平台教什么，平台就用什么」的示范效应。
2. 安全（Spring Security）、ORM（MyBatis-Plus/JPA）、定时任务、参数校验等学习平台所需能力均有成熟组件，开发省心。
3. 团队若更倾向 Go（追求轻量部署与开发速度），Gin + GORM 为备选方案，架构与接口契约不变，替换成本可控。

**辅助说明**：Python (FastAPI) 适合快速原型与 AI 模块（如未来接入智能问答），可作为独立微服务按需引入，不作为主后端。

### 6.4 数据库选型

| 项 | 选型 | 说明 |
| ---- | ---- | ---- |
| 主数据库 | **PostgreSQL 16** | 功能强大（JSONB、全文检索、窗口函数）、更贴近 SQL 标准；内容的结构化元数据与正文均存于此 |
| 缓存 | Redis 7 | 热门内容缓存、排行榜、会话/Token 黑名单、计数器 |
| 全文检索 | 先用 PostgreSQL 内置全文检索；数据量大或需求复杂后评估 Elasticsearch | 降低初期组件复杂度 |

**与学习目标的兼容**：产品需求中 MySQL 是学习者必须掌握的技能。方案：平台主库使用 PostgreSQL，同时在课程内容中提供 **MySQL 对照知识点**（两者 SQL 共通度高，差异点集中在数据类型、函数与索引实现）；实验环境可提供 MySQL 实例供练习，不影响平台自身架构。

### 6.5 基础设施与部署

| 项 | 方案 |
| ---- | ---- |
| 开发环境 | Docker Compose 一键拉起 PostgreSQL + Redis；前后端分别启动 |
| 生产部署 | 云服务器 + Docker Compose（Nginx / API / PostgreSQL / Redis）起步；规模增长后迁移 Kubernetes |
| CI/CD | GitHub Actions：推送触发测试 → 构建镜像 → 部署 |
| 日志监控 | 初期：结构化日志 + 服务器告警；后续：Prometheus + Grafana |

| PathStage | 路线阶段 | id, path_id, name, description, sort_order, suggest_duration |
| PathItem | 路线节点（指向课程/知识点） | id, stage_id, lesson_id, sort_order, is_branch, prereq_item_id |
| Course | 课程 | id, domain_id, slug, title, summary, difficulty(L1–L4), status, author_id |
| Chapter | 章节 | id, course_id, title, sort_order |
| Lesson | 知识点 | id, chapter_id, slug, title, content_md, est_minutes, status |
| Resource | 精选外链资源 | id, lesson_id, title, url, type(doc/book/video/tool), difficulty, note |
| Quiz | 测验 | id, scope_type(lesson/chapter/course), scope_id, title |
| Question | 题目 | id, quiz_id, type(single/multi), stem, options(jsonb), answer, explanation |
| Progress | 学习进度 | id, user_id, lesson_id, status(learning/done), completed_at；唯一约束 (user_id, lesson_id) |
| UserAnswer | 作答记录 | id, user_id, question_id, answer, is_correct, created_at |
| Favorite | 收藏 | id, user_id, target_type(course/lesson/path), target_id |
| Feedback | 内容纠错反馈 | id, user_id, lesson_id, content, status(pending/resolved) |
| Note（P2） | 学习笔记 | id, user_id, lesson_id, content, visibility(private/public) |
| Comment（P2） | 评论 | id, user_id, lesson_id, content, status, created_at |

### 7.2 核心关系

```
Domain 1 ── N Course 1 ── N Chapter 1 ── N Lesson 1 ── N Resource
Domain 1 ── N LearningPath 1 ── N PathStage 1 ── N PathItem ── 1 Lesson
User 1 ── N Progress N ── 1 Lesson          （唯一约束：user + lesson）
User 1 ── N UserAnswer N ── 1 Question
Course/Chapter/Lesson/Quiz 通过 scope_type + scope_id 灵活关联测验
```

**设计要点：**

1. `PathItem` 将「路线」与「内容」解耦：路线图是知识点的编排视图，同一知识点可出现在多条路线。
2. `Progress` 以知识点为最小粒度，章节/课程/领域进度均为聚合查询（配合缓存）。
3. 内容表（Course/Chapter/Lesson）统一带 `status`（草稿/待审核/发布）与作者字段，支撑后台审核流。
4. 预留软删除字段（`deleted_at`）与内容版本表（`lesson_revision`），满足回溯需求。

## 9. 里程碑规划

| 里程碑 | 范围 | 验收标准 | 预估周期 |
| ---- | ---- | ---- | ---- |
| **M0 准备** | 需求评审、原型草图（首页/路线图/课程页/知识点页）、开发环境与仓库初始化 | 原型评审通过；前后端脚手架可运行 | 1 周 |
| **M1 MVP** | F1 领域导航、F2 路线图、F3 课程内容、F4 进度跟踪、F7 基础用户系统；内容填充 2 个示范领域（前端 + 计算机基础） | 完整链路可走通：注册 → 选领域 → 学知识点 → 标记完成 → 继续学习；移动端可正常浏览 | 4–6 周 |
| **M2 完善期** | F5 选择题测验与错题本、F6 搜索、F8 后台管理；内容扩展至 5 个领域（+后端、数据库、开发工具） | 后台可独立完成内容上架与题目录入；测验闭环可用 | 4 周 |
| **M3 扩展期** | F9 社区（笔记/评论）、SEO 强化（预渲染/Nuxt）、内容全量 9 领域、代码判题专项评估 | 全领域覆盖；SEO 收录正常；社区功能灰度上线 | 持续迭代 |

**里程碑原则**：每个里程碑以「可演示、可上线」为准，先窄后宽——MVP 用 2 个领域打磨完整体验闭环，再横向复制内容。

## 10. 风险与应对

| 风险 | 影响 | 概率 | 应对策略 |
| ---- | ---- | ---- | ---- |
| 内容生产成本高、更新慢 | 平台空壳化，用户无内容可学 | 高 | 「原创骨架 + 外链填充」降低单点工作量；先做 2 个示范领域；统一内容模板（3.4）；后台提供批量导入 |
| 初学者找不到方向、流失快 | 核心价值不成立 | 中 | 「找方向」问答引导（F1.2）；路线图显式依赖降低规划成本；打卡与继续学习降低回归成本 |
| 团队规模小、周期超预期 | 上线拖延 | 中 | MVP 严格聚焦 P0；选型保守成熟（Vue + Spring Boot）；测验/社区等复杂功能后置 |
| 技术选型中途变更 | 返工 | 低 | 前后端分离 + API 契约先行；后端 Java/Go 可替换；数据模型与框架解耦 |
| 在线判题的安全与成本 | 判题功能引入漏洞或资源滥用 | 中 | 一期不做代码判题；若启动专项，采用容器沙箱 + 资源配额 + 队列限流 |
| 内容被恶意爬取/转载 | 版权与流量损失 | 中 | robots 策略、接口限流、内容加水印（可选）、版权声明 |
| 单点故障（服务器/数据库） | 服务不可用、数据丢失 | 低 | Docker 化便于迁移；每日备份 + 异地留存；重要操作软删除 |
