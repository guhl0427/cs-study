## 0. 与完整版的差异一览

本版本是完整版的**裁剪与降级替代方案**，产品定位、领域体系、内容结构完全继承完整版，仅部署形态与用户数据归属不同。

| 维度 | 完整版 | 纯前端版（本文档） |
| ---- | ---- | ---- |
| 部署形态 | Nginx + Spring Boot + PostgreSQL + Redis | 纯静态站点（CDN / GitHub Pages / 对象存储均可） |
| 账号体系（F7） | 邮箱注册 + JWT 会话 | **本地档案**：无注册登录，身份与数据存于浏览器 |
| 进度存储 | 数据库，跨设备同步 | localStorage，**仅本设备**；以「导出/导入」替代同步 |
| 后台管理（F8） | 后台 SPA + 审核流 | **内容工程化**：内容即文件，Git 分支即草稿，合并即发布 |
| 热门推荐（F1.4） | 基于真实学习人数统计 | 编辑精选推荐位（静态配置） |
| 内容纠错（F3.6） | 站内反馈进后台队列 | 跳转 GitHub Issue（预填模板） |
| 内容版本（F3.7） | 内容版本表 | Git 提交历史 |
| 社区功能（F9） | 二期预留 | **移出范围**（依赖后端） |
| 新增能力 | — | 数据导出/导入（F7）、PWA 离线学习（F10） |
| 里程碑周期 | M1 约 4–6 周 | M1 约 3–4 周（无后端开发） |

## 1. 项目概述

### 1.1 项目背景

继承完整版 1.1：CS 学生与初学者面临「不知道学什么、按什么顺序学、学到什么程度、难以坚持」四大痛点。

纯前端版的出发点：**先把「学习地图 + 结构化内容 + 本地进度反馈」这个核心价值做出来并交付**，不为账号体系与后端基础设施所阻塞。平台的内容骨架（领域/路线/课程/知识点）均为静态资产，天然适合纯前端形态。

### 1.2 产品定位

面向**计算机专业学生与初学者**的结构化学习平台：以「技术领域 → 学习路线 → 课程内容 → 本地进度反馈」为主线。

一句话描述：**为 CS 初学者提供一张清晰的「学习地图」，打开就能学，进度随身存。**

与完整版的定位差异：

- 「陪他走完全程」中的**陪伴手段**由「云端账号 + 打卡记录」改为「浏览器本地记录 + 数据导出带走」。
- 平台承诺**不收集任何用户数据**——所有学习记录只存在于用户自己的浏览器中，隐私即卖点。

### 1.3 产品目标

| 目标 | 衡量标准 |
| ---- | ---- |
| 让初学者 3 分钟内找到适合的学习方向 | 可用性测试：新用户 3 分钟内进入领域/路线页的比例 |
| 提供体系化、可执行的学习路线 | 每个领域均有完整路线图（阶段 + 知识点 + 依赖关系） |
| 提供高质量结构化内容 | 每个知识点均有原创讲解 + 精选外链资源 |
| 建立本地学习闭环 | 标记完成 → 继续学习 → 打卡日历 → 导出备份，全链路可用 |
| 零基础设施即可上线 | 纯静态产物，任意静态托管平台可部署 |

### 1.4 价值主张（与现有产品的差异化）

| 维度 | 本平台 | roadmap.sh 类 | 教程网站类 | 视频课程类 |
| ---- | ---- | ---- | ---- | ---- |
| 领域全景导航 | ✅ | ✅ | ❌ | ❌ |
| 结构化站内内容 | ✅ | ❌ | ✅ | ✅ |
| 学习路线与依赖关系 | ✅ | ✅ | 部分 | ❌ |
| 进度跟踪与打卡 | ✅（本地） | 部分 | ❌ | 部分 |
| 中文原生内容 | ✅ | ❌（英文为主） | ✅ | ✅ |
| 精选外链资源整合 | ✅ | 部分 | ❌ | ❌ |
| **无需注册、零数据收集** | ✅ | ❌ | ❌ | ❌ |

### 1.5 成功指标（初期参考）

无后端即无埋点上报，指标由**可用性测试与技术验收**替代运行时统计：

- 可用性测试（5–8 名目标用户）：新用户 3 分钟内进入某个领域/路线页面的比例 ≥ 40%
- 「继续学习」入口在回访场景中被使用的比例 ≥ 50%（可用性测试观察）
- Lighthouse Performance ≥ 90、SEO ≥ 95（核心内容页）
- 首屏加载 ≤ 1.5s（CDN 部署、常规宽带）
- 进度数据导出 → 换浏览器导入 → 数据完整恢复（验收演练 0 失败）

## 2. 目标用户与角色

### 2.1 用户画像

继承完整版 2.1，不变：

| 画像 | 描述 | 核心诉求 |
| ---- | ---- | ---- |
| **在校 CS 学生**（大一~大三） | 已修/正在修专业课程，想补齐工程实践方向，为实习、校招做准备 | 清晰的就业方向路线图、与校招要求对齐的知识清单、项目实战指引 |
| **转行初学者** | 非计算机专业出身，自学转行，基础薄弱 | 从零开始的平滑路径、明确「先学什么后学什么」、避免被进阶内容劝退 |
| **自学进阶者** | 已掌握一门语言/一个方向，想扩展技术面 | 按需检索知识点、进阶内容与优质外链资源 |

### 2.2 系统角色与权限

无账号体系，角色简化为一种使用姿态：

| 角色 | 说明 |
| ---- | ---- |
| **本地学员**（默认） | 打开网站即为本地学员：可浏览全部内容，学习进度/打卡/错题/收藏自动记录在**本浏览器** localStorage 中，无需任何注册动作 |
| **游客**（清空数据后） | 清空本地数据或使用隐私模式时即游客：可浏览全部内容，可试用进度标记（刷新后丢失） |

**设计决策**：不做「显式开启记录」的开关——默认记录、随时可清，比「先选择再使用」的摩擦更小。个人信息（昵称/头像）完全可选，不填不影响任何功能。

## 3. 技术领域与内容体系

> 本章完整继承完整版第 3 章，内容骨架不变。

### 3.1 设计原则

1. **领域即入口**：首页按领域组织，每个领域是一张独立的「学习地图」。
2. **难度统一分级**：所有知识点、课程、路线阶段统一使用四级难度体系。
3. **原创骨架 + 精选外链**：每个知识点由站内原创讲解构成骨架，并挂载经过筛选的优质外部资源作为延伸。
4. **依赖关系显式化**：知识点之间的前置关系在路线图中显式标注。

**难度分级体系（全站统一）：**

| 等级 | 名称 | 描述 |
| ---- | ---- | ---- |
| L1 | 入门 | 零基础可学，掌握概念与基本使用 |
| L2 | 基础 | 能独立完成简单任务，理解常用特性 |
| L3 | 进阶 | 理解原理，能解决较复杂问题 |
| L4 | 精通 | 深入底层与最佳实践，能指导他人 |

### 3.2 领域总览

| # | 领域 | 定位 | 建议先修 | 难度跨度 |
| ---- | ---- | ---- | ---- | ---- |
| ① | 计算机基础 | 全领域的地基，CS 学生必修 | 无 | L1–L3 |
| ② | 编程语言 | 第一门语言的起点 | 计算机基础（可并行） | L1–L4 |
| ③ | 前端开发 | 就业主流方向之一 | ② 中的 JavaScript/TypeScript | L1–L4 |
| ④ | 后端开发 | 就业主流方向之一 | ② 中的一门语言 + ① | L1–L4 |
| ⑤ | 数据库 | 后端必配，独立技能 | ④（可并行） | L1–L3 |
| ⑥ | 开发工具与环境 | 全领域通用生产力 | 无 | L1–L2 |
| ⑦ | 软件工程 | 从「会写代码」到「会做工程」 | ⑥ Git | L1–L3 |
| ⑧ | AI 与数据 | 新兴热点方向 | ② Python + ① 基础 | L2–L4 |
| ⑨ | 选修拓展 | 安全、移动端等兴趣方向 | 视子方向而定 | L2–L4 |

**典型学习起点推荐（用于首页引导）：**

- 完全零基础 → ⑥ Git/IDE → ② C 或 Python 入门 → ① 计算机基础（并行）→ 选定方向（③/④）
- 在校 CS 学生 → ① 计算机基础查漏 → ④ 后端 或 ③ 前端 → ⑤ 数据库 → ⑦ 软件工程 → 项目实战
- 转行求快 → ② Python → ④ 后端（Python/FastAPI 路线）→ ⑤ SQL → ⑥ Git/Docker

### 3.3 各领域详细说明

#### ① 计算机基础

**简介**：计算机科学与技术的地基，决定学习者后续天花板。与校内课程对应，可辅助专业课学习。

**适合人群**：所有初学者（尤其是 CS 在校生）；建议与前端/后端方向并行学习。

**前置知识**：无。

**技术清单：**

| 技术点 | 内容范围 | 难度 | 建议时长 |
| ---- | ---- | ---- | ---- |
| 数据结构与算法 | 线性表、栈与队列、哈希表、树、堆、图、排序与查找、递归、动态规划入门 | L1–L3 | 8–12 周 |
| 计算机网络 | 网络分层模型（OSI/TCP-IP）、HTTP/HTTPS、TCP/UDP、DNS、抓包初步 | L1–L3 | 4–6 周 |
| 操作系统 | 进程与线程、内存管理、文件系统、I/O 与中断 | L2–L4 | 6–8 周 |
| 计算机组成原理 | 进制与编码、CPU 与指令、存储层次结构 | L2–L3 | 4–6 周 |

**精选外链类型**：《图解 HTTP》《计算机网络：自顶向下方法》《操作系统导论》《深入理解计算机系统（CSAPP）》；LeetCode / 洛谷刷题平台；相关公开课。

**学习阶段**：S1 数据结构与算法 + 网络基础 → S2 操作系统 + 组成原理 → S3 结合后端方向综合应用。

#### ② 编程语言

**简介**：第一门编程语言的起点与多语言拓展。原则：**主修 1 门 + 辅修 1 门**，忌贪多。

**适合人群**：零基础新手（从 C 或 Python 起步）、需第二门语言的进阶者。

**前置知识**：计算机基础（可并行）。

**技术清单：**

| 语言 | 定位 | 难度 | 建议时长 | 说明 |
| ---- | ---- | ---- | ---- | ---- |
| Python | 首选通用入门；数据/AI 方向基础 | L1–L2 | 3–4 周 | 语法友好，反馈快 |
| C | 理解内存、指针与底层机制 | L2–L3 | 4–6 周 | 与《组成原理》联动，CS 学生建议接触 |
| Java | 后端就业主流语言 | L1–L3 | 8–12 周 | 面向对象 + 生态庞大 |
| Go | 后端/云原生方向，语法精简 | L1–L2 | 3–4 周 | 上手快，部署简单 |
| JavaScript | Web 前端核心语言 | L1–L3 | 4–6 周 | 归入前端路线亦可 |
| TypeScript | JS + 类型系统 | L2–L3 | 2–3 周 | 前端框架必备 |
| C++ | 系统级/高性能/竞赛 | L3–L4 | 12 周+ | 选修 |
| Rust | 内存安全的新兴系统语言 | L3–L4 | 选修 | 兴趣驱动 |

**学习阶段**：S1 第一门语言（Python 或 C）→ S2 方向语言（Java / Go / JS+TS）→ S3 第二语言与范式拓展（选修）。

#### ③ 前端开发

**简介**：从页面三件套到框架与工程化的完整前端路线。

**适合人群**：喜欢可视化反馈、面向 Web 开发就业的学习者。

**前置知识**：JavaScript / TypeScript（可在本路线内学习）。

**技术清单：**

| 技术点 | 内容范围 | 难度 | 建议时长 |
| ---- | ---- | ---- | ---- |
| HTML5 | 语义化标签、表单、多媒体、可访问性初步 | L1 | 1–2 周 |
| CSS3 | 盒模型、选择器、Flex/Grid 布局、定位、动画过渡 | L1–L2 | 2–3 周 |
| JavaScript (ES6+) | 基础语法、DOM 与事件、异步编程（Promise/async）、模块化 | L1–L3 | 4–6 周 |
| CSS 进阶 | 响应式设计、Sass/Less、Tailwind CSS | L2 | 1–2 周 |
| TypeScript | 类型系统、泛型、配置与工程接入 | L2–L3 | 2–3 周 |
| Vue 3 生态 | Vue 3 组合式 API、Vue Router、Pinia、Element Plus / Naive UI | L2–L3 | 4–6 周 |
| React 生态 | React 18 Hooks、React Router、Redux Toolkit / Zustand、Ant Design | L2–L3 | 4–6 周 |
| 工程化 | Node.js 与 npm/pnpm 基础、Vite、ESLint/Prettier、环境变量 | L2 | 2 周 |
| 浏览器原理与性能优化（进阶） | 渲染流程、事件循环、跨域、打包优化、懒加载 | L3–L4 | 2–3 周 |
| SSR / 元框架（进阶选修） | Nuxt / Next.js | L3–L4 | 选修 |

**说明**：Vue 与 React **二选一深入**（另一门了解即可），路线图中作为并列分支呈现。

**学习阶段**：S1 HTML/CSS/JS 三件套 → S2 TypeScript + 框架（Vue 或 React）→ S3 生态与工程化 → S4 原理、性能与 SSR（进阶）。

#### ④ 后端开发

**简介**：以「语言 + Web 框架 + 数据存储 + 中间件」为主线的服务端开发路线，含 Java、Go、Python 三条语言分支。

**适合人群**：对系统逻辑、数据流转感兴趣，面向服务端开发就业的学习者。

**前置知识**：一门编程语言（②）、计算机网络与 SQL 基础（①⑤可并行）。

**技术清单：**

| 技术点 | 内容范围 | 难度 | 建议时长 |
| ---- | ---- | ---- | ---- |
| Web 通用基础 | HTTP 深入、RESTful API 设计、JSON、Cookie/Session、JWT/OAuth2 认证授权 | L1–L3 | 2–3 周 |
| Java 方向 | Java SE → Maven/Gradle → Spring Boot → Spring MVC → MyBatis-Plus / Spring Data JPA → Spring Security →（进阶）JVM 与调优 | L1–L4 | 10–14 周 |
| Go 方向 | Go 语法 → go mod → Gin → GORM →（进阶）gRPC、并发模型 | L1–L3 | 6–8 周 |
| Python 方向 | Flask / Django / FastAPI 三框架概览 + 一框架深入 | L1–L3 | 4–8 周 |
| 缓存 | Redis 数据类型、缓存穿透/击穿/雪崩、持久化 | L2–L3 | 1–2 周 |
| 消息队列 | RabbitMQ / Kafka 基本使用与典型场景（异步、解耦、削峰） | L2–L3 | 1–2 周 |
| 搜索（选修） | Elasticsearch 基础使用 | L3 | 选修 |
| 微服务与分布式（进阶选修） | 服务注册发现、网关、分布式事务、Spring Cloud | L3–L4 | 选修 |

**学习阶段**：S1 语言巩固 + Web 基础 → S2 Web 框架入门（CRUD 项目）→ S3 数据库 + 缓存整合 → S4 认证、测试、部署的完整项目实战 → S5 微服务/分布式（选修）。

#### ⑤ 数据库

**简介**：从 SQL 语言到数据库设计与优化，覆盖关系型、缓存型、文档型三类存储。

**适合人群**：所有后端学习者（必修）；数据方向学习者。

**前置知识**：无硬性前置（与后端方向并行最佳）。

**技术清单：**

| 技术点 | 内容范围 | 难度 | 建议时长 |
| ---- | ---- | ---- | ---- |
| SQL 语言 | DDL/DML/DQL、多表联查（JOIN）、聚合与分组、子查询、窗口函数初步 | L1–L2 | 2–3 周 |
| MySQL | 安装与配置、存储引擎、索引原理、事务与隔离级别、SQL 优化（EXPLAIN） | L1–L3 | 4–5 周 |
| PostgreSQL | 与 MySQL 对照学习、JSONB、数组类型、CTE、全文检索初步 | L2–L3 | 3–4 周 |
| 数据库设计 | ER 建模、三大范式、反范式权衡、库表设计实践 | L2–L3 | 2 周 |
| Redis | 数据类型与场景、缓存策略、主从与持久化概念 | L2–L3 | 1–2 周 |
| MongoDB（选修） | 文档模型、聚合管道、适用场景 | L2–L3 | 选修 |
| ORM | MyBatis / JPA（Java）、GORM（Go）、SQLAlchemy（Python） | L2 | 1 周 |
| 分库分表与高可用（进阶选修） | 读写分离、分区、分库分表 | L4 | 选修 |

**说明**：MySQL 与 PostgreSQL 的 SQL 语言高度共通，课程内容以「一套 SQL + 两个数据库的对照差异」组织。

**学习阶段**：S1 SQL 语言 → S2 深入一个关系型库（MySQL 或 PostgreSQL）→ S3 设计与优化 → S4 Redis 与 NoSQL → S5 分库分表（选修）。

#### ⑥ 开发工具与环境

**简介**：全方向通用的生产力基础设施，建议在第一周就学 Git 与 IDE 基础。

**适合人群**：所有学习者。

**前置知识**：无。

**技术清单：**

### 3.4 内容生产规范

每个知识点页面遵循统一模板：

1. **一句话定义**：这是什么、解决什么问题。
2. **概念讲解**：配图 / 类比，控制在初学者可读的篇幅。
3. **代码示例**：可运行、带注释，附运行结果。
4. **常见坑**：初学者高频错误与排查思路。
5. **小练习**：1–3 道自测题（衔接 F5 测验模块）。
6. **精选外链**：官方文档 / 书籍章节 / 公开课，标注类型、难度、推荐理由。

**纯前端版补充——内容文件规范**：

- 知识点正文以 Markdown 文件存放于仓库 `content/` 目录，frontmatter 承载结构化元数据（`id`、`slug`、`title`、`difficulty`、`est_minutes`、`tags` 等），字段约束见第 7 章。
- 领域/课程/章节/路线图/测验以外置 JSON 文件描述，通过 id/slug 相互引用。
- 构建期执行校验：schema 校验、slug 唯一性、引用完整性（路线图节点指向的 lesson 必须存在）、外链格式检查。校验不通过则构建失败（见 F8）。

## 5. 非功能需求

| 类别 | 需求 |
| ---- | ---- |
| **性能** | 纯静态资源 + CDN：首屏加载 ≤ 1.5s（常规宽带）；路由切换无服务端往返；内容页按路由懒加载与代码分割 |
| **SEO** | 课程/知识点页面**必须**可被搜索引擎收录：采用 SSG（构建期静态化）或预渲染；规范 meta 标题/描述；sitemap.xml；语义化 HTML。内容均为构建期已知，SSG 是自然选择而非补丁 |
| **安全** | Markdown 渲染必须白名单过滤防 XSS；外链资源统一 `rel="noopener noreferrer"`；无后端故无注入/鉴权面；**不在 localStorage 存任何敏感数据**（本产品无敏感数据可言，此条作为设计红线） |
| **兼容性** | 近两年主流浏览器（Chrome/Edge/Firefox/Safari）；移动端响应式适配（≥375px 宽度可正常阅读与操作）；localStorage 不可用时（隐私模式等）降级为「游客试用」并提示，不得报错白屏 |
| **可用性** | 静态托管天然多副本；发布即回滚（重新部署上一版本产物）；清空数据等破坏性操作二次确认 |
| **数据** | 本地存储用量控制在 ≤ 1MB（远低于 5MB 配额）；作答记录等日志型数据设条数上限；导出文件向后兼容策略见 7.3 |
| **可维护性** | TypeScript 全量覆盖，内容 schema 类型与前端类型同源（单一类型定义来源）；CI 执行内容校验 + 构建 + 冒烟测试；README 与内容贡献指南齐全 |

## 6. 技术架构与选型

### 6.1 总体架构

```
        ┌──────────────────────────────┐
        │         用户（浏览器）          │
        └──────────────┬───────────────┘
                       │ HTTPS
        ┌──────────────▼───────────────┐
        │     静态托管（CDN / Pages）     │
        │  HTML + JS + CSS + 内容数据     │
        └──────────────────────────────┘

  构建期（开发机 / CI）：
  ┌────────────────────────────────────────────┐
  │ content/（MD + JSON）                        │
  │   → schema 校验 → 引用完整性检查              │
  │   → 生成搜索索引 → 生成路由表                  │
  │   → Vite 构建 / SSG 预渲染 → 静态产物          │
  └────────────────────────────────────────────┘
```

- **没有运行时服务端**：所有「接口」都是构建期生成或本地计算。
- 内容元数据打包为 JSON 模块（按领域分片、按需加载）；正文 Markdown 构建期编译为 HTML 字符串或运行时渲染，二选一在 M0 定案。

### 6.2 前端选型

| 项 | 选型 | 说明 |
| ---- | ---- | ---- |
| 框架 | **Vue 3 + TypeScript** | 与完整版一致，保证未来后端接入时前台代码可平移 |
| 构建 | Vite | 开发热更新快，构建简单 |
| 渲染模式 | **SSG 优先**：VitePress 式构建期静态化，或 Nuxt 3 `nuxt generate`；备选 vite-prerender 插件 | SEO 是硬性需求（§5），且内容构建期已知，SSG 成本最低。M0 定案 |
| 状态管理 | Pinia | Vue 官方推荐 |
| 路由 | Vue Router 4 | 内容页路由由内容文件生成 |
| UI 组件 | Naive UI / 自建设计系统 | 无后台，无需 Element Plus |
| 样式 | Tailwind CSS | 快速实现响应式布局 |
| Markdown 渲染 | markdown-it + Shiki | 代码高亮质量好；Shiki 构建期高亮优先（零运行时开销） |
| 本地搜索 | MiniSearch 或 FlexSearch | 构建期生成索引 JSON，前端内存检索 |
| 图表（学习统计） | 轻量方案：ECharts 按需引入或纯 SVG 自绘 | 仅条形图/日历热力图，避免引入完整图表库 |

### 6.3 关键架构设计：服务适配层

为「未来接后端不返工」而设，是本版本最重要的架构约束：

```
src/
├── api/                 # 服务适配层：接口契约 + 实现
│   ├── contracts.ts     # 接口签名（getDomain / getPath / getProgress ...）
│   ├── local/           # 本地实现：静态内容数据 + localStorage
│   └── remote/          # （未来）HTTP 实现，占位不开发
├── storage/             # 本地存储模块：版本化 schema + 迁移器
├── content/             # 构建期生成的内容数据（不手写）
├── store/               # Pinia
├── pages/、components/  # 页面与组件
└── types/               # 全站唯一类型定义来源（内容 schema + 用户数据 schema）
```

- 页面只允许调用 `api/contracts.ts` 中定义的接口，**禁止**直接读内容 JSON 或直接操作 localStorage。
- M3 评估后端接入时，新增 `api/remote/` 实现并按环境切换，页面层零改动。

### 6.4 代码仓库结构建议（Monorepo）

```
cs-study/
├── docs/                  # 需求、设计文档
├── content/               # 静态内容（领域/课程/章节/知识点/路线/题目）
├── frontend/              # 前台 SPA（Vue 3 + TS + SSG）
```

## 7. 数据模型与本地存储设计

### 7.1 内容数据模型（构建期静态数据，用户只读）

与完整版 §7 实体清单一致，差异：所有实体去掉 `status/author_id/deleted_at` 等审核流字段（无后台审核流，发布即存在），以 TypeScript 接口 + JSON 文件表达：

| 实体 | 关键字段 | 文件组织 |
| ---- | ---- | ---- |
| Domain | id, slug, name, icon, summary, sortOrder | `content/domains.json`（数组） |
| LearningPath | id, domainId, name, description, targetAudience | `content/paths/{pathId}.json` |
| PathStage | id, pathId, name, description, sortOrder, suggestDuration | 内嵌于路线文件 |
| PathItem | id, stageId, lessonId, sortOrder, isBranch, prereqItemIds | 内嵌于路线文件（依赖改为数组，支持多前置） |
| Course | id, domainId, slug, title, summary, difficulty | `content/courses/{courseId}.json` |
| Chapter | id, courseId, title, sortOrder | 内嵌于课程文件 |
| Lesson | id, chapterId, slug, title, estMinutes, tags, contentMdRef | 元数据内嵌于章节；正文为 `content/lessons/{lessonId}.md` |
| Resource | id, lessonId, title, url, type(doc/book/video/tool), difficulty, note | 内嵌于知识点 frontmatter |
| Quiz / Question | id, scopeType(lesson/chapter/course), scopeId, stem, options[], answer, explanation | `content/quizzes/{quizId}.json` |

### 7.2 用户数据模型（localStorage，用户私有）

| 存储 Key | 内容 | 结构示意 |
| ---- | ---- | ---- |
| `cs-study:schemaVersion` | 存储结构版本号 | `2` |
| `cs-study:profile` | 本地档案 | `{ nickname, avatarId, startDate, activePathId }` |
| `cs-study:progress` | 知识点进度 | `{ [lessonId]: { status: "learning"\|"done", completedAt } }` |
| `cs-study:favorites` | 收藏 | `{ [targetType_targetId]: { targetType, targetId, createdAt } }` |
| `cs-study:answers` | 作答记录（错题本数据源） | `{ [questionId]: { answer, isCorrect, answeredAt } }`（上限 500 条，FIFO） |
| `cs-study:guide` | 找方向问答结果 | `{ answers, recommendedPathId, completedAt }` |
| `cs-study:lastVisit` | 最近学习 | `{ lessonId, courseId, at }` |

**设计要点**：

1. 学习日历、streak、各领域进度等统计**不单独存储**，一律从 `progress` 推导——单一数据源，避免一致性问题。
2. 所有 Key 统一前缀 + 独立 Key（而非一个大 JSON），便于按类读写与迁移。
3. 内容 ID 与用户数据解耦：内容变更（删除/调整知识点）后，用户数据中的孤儿记录在读取时静默忽略并在下次导出时清理。

### 7.3 版本化与迁移

- 用户数据结构带 `schemaVersion`；应用启动时若检测到旧版本，执行迁移器（`storage/migrations/` 中按版本链式升级）。
- 导出文件结构：`{ app: "cs-study", schemaVersion, exportedAt, data: { profile, progress, favorites, answers, guide, lastVisit } }`；导入时按迁移器升级到当前版本后合并/覆盖。

## 9. 里程碑规划

| 里程碑 | 范围 | 验收标准 | 预估周期 |
| ---- | ---- | ---- | ---- |
| **M0 准备** | 需求评审、原型草图（首页/路线图/课程页/知识点页）、脚手架初始化、**内容 schema 与目录规范定案**、SSG 方案与托管平台定案 | 原型评审通过；脚手架 + 内容脚手架工具可运行 | 1 周 |
| **M1 MVP** | F1 领域导航、F2 路线图、F3 课程内容、F4 进度跟踪（含 4.6/4.7 导出与提示）、F7 本地档案与数据管理；内容填充 2 个示范领域（前端 + 计算机基础） | 完整链路可走通：打开即学 → 标记完成 → 关闭浏览器 → 回访继续学习 → 导出 → 换浏览器导入恢复；移动端可正常浏览 | 3–4 周 |
| **M2 完善期** | F5 选择题测验与错题本、F6 搜索、SSG/SEO 落地验收、F8 内容工程化流程（CI 校验 + PR 预览部署）；内容扩展至 5 个领域（+后端、数据库、开发工具） | Lighthouse SEO ≥ 95 且内容页可被收录；内容 PR 全流程走 CI 校验；测验闭环可用 | 3 周 |
| **M3 扩展期** | 内容全量 9 领域、F10 PWA 离线、**后端接入评估**（若启动，按 6.3 契约实现 `api/remote/`，恢复账号体系与跨端同步） | 全领域覆盖；离线场景可用；后端接入产出可行性结论 | 持续迭代 |

**里程碑原则**：继承完整版「每个里程碑可演示、可上线，先窄后宽」；M1 交付的完整度高于完整版 M1（省去后端联调），但**显式接受单设备限制**。

## 10. 风险与应对

| 风险 | 影响 | 概率 | 应对策略 |
| ---- | ---- | ---- | ---- |
| **用户清缓存/隐私模式导致进度丢失** | 信任受损，核心闭环失效 | 高 | 知识点页与个人中心持续可见「仅存本设备」提示；累计学习 ≥ 7 天时引导导出备份；4.6 导出作为 P0 交付 |
| localStorage 配额/不可用 | 数据写入失败 | 低 | 用量控制 ≤ 1MB（§5）；写入失败兜底为内存态 + 显著提示「进度无法保存」；隐私模式降级为游客试用 |
| 题目答案随前端包下发 | 「测验」可被查看答案 | 高（必然） | 定位自测工具（F5 说明），不宣称防作弊；如需严肃测验则属后端接入范畴 |
| 多设备不同步 | 跨设备用户体验断裂 | 中 | 导出/导入明示为迁移手段；UI 不出现「云同步」误导性文案；M3 评估后端 |
| 内容生产成本高、更新慢 | 平台空壳化 | 高 | 继承完整版策略（原创骨架 + 外链填充、2 领域起步、统一模板）；新增 F8.5 内容脚手架降低单点成本 |
| 初学者找不到方向、流失快 | 核心价值不成立 | 中 | 继承完整版策略（找方向问答、显式依赖、打卡与继续学习） |
| SSG/SEO 方案落地困难 | 收录失败 | 低 | 内容构建期已知，SSG 技术成熟；M2 设硬性验收指标（Lighthouse SEO ≥ 95） |
| 单一类型定义漂移 | 内容校验与前端类型不一致 | 中 | `types/` 单一来源（§6.3）；CI schema 校验兜底 |
