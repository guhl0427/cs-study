## 1. 背景

完整版需求规划（2026-11-21 初稿）描述了「Nginx + Spring Boot + PostgreSQL + Redis」的全量产品形态。项目实际按**纯前端版**先行交付并已上线（2026-11-23 状态：v0.4.0，9 领域 / 20 门课 / 107 篇知识点 / 67 个测验，全静态部署于 GitHub Pages）。

完整版文档已归档，其中仍然有效的后端规划资产抽出到本文档，作为纯前端版里程碑 M3 的遗留项「**后端接入评估**」的工作底稿。纯前端版在架构上已预留接入点（§6.3）：页面层只允许调用 `api/contracts.ts` 定义的接口，未来新增 `api/remote/` HTTP 实现并按环境切换，**页面层零改动**。

## 2. 评估要回答的问题

| # | 问题 | 备注 |
| ---- | ---- | ---- |
| 1 | **是否启动**后端？ | 纯前端版已覆盖核心学习闭环；后端解决的增量问题集中在跨设备同步与社区（见 §3） |
| 2 | 若启动，**范围切多大**？ | 完整版是全量蓝图（含后台管理、社区）；可评估「最小后端」方案——只做用户域（账号 + 进度同步），内容仍走 Git 静态分发（依据见 §5 注记） |
| 3 | **选型**：Spring Boot 还是 Gin？ | 完整版主选 Spring Boot 3.x + Java 21，Gin 为备选（见 §4.2），接口契约不变、可替换 |
| 4 | **环境前置**是否就绪？ | 本机缺 JDK 21 与 Docker（2026-11-21 环境基线）；PostgreSQL / Redis 计划走 Docker Compose |

## 3. 后端能解锁什么（对照纯前端版现状）

| 能力 | 纯前端版现状 | 后端可提供 | 完整版需求 |
| ---- | ---- | ---- | ---- |
| 跨设备同步 | localStorage，仅本设备；导出/导入作为迁移手段 | 账号体系 + 服务端进度存储，多端同步 | F7（P0） |
| 社区 | 无 | 学习笔记 / 评论 / 问答 / 激励体系 | F9（P2） |
| 内容后台 | `content/` 静态文件 + Git PR + CI 校验 + PR 预览部署 | 在线 CRUD、草稿→审核→发布流、题库管理、用户管理 | F8（P1） |
| 内容纠错反馈 | 无上报通道（纯前端无后端可提交） | 反馈队列与处理流程 | F3.6 |
| 全文检索 | 构建期静态索引 + 前端内存检索 | PostgreSQL 全文检索（量大后评估 ES） | F6.3（P2） |
| 热门统计 | 编辑精选静态推荐位（无运行时统计） | PV/UV、完课率、热门排行 | F8.6 |

> **注记（评估视角，非结论）**：纯前端版的内容工程化链路（静态内容 + Git 管理 + CI 校验 + PR 预览部署）已实质替代完整版 F8「后台管理」的核心价值；后端的真正增量集中在**用户数据域**（F7 账号与跨设备同步）与**社区**（F9）。这是 §2 问题 2 中「最小后端」方案的依据，但不预设评估结论。

## 4. 架构与选型基线（完整版 §6 摘录）

### 4.1 总体架构

```
                    ┌─────────────────────────────┐
                    │          用户 / 管理员        │
                    └──────────┬──────────────────┘
                               │ HTTPS
                    ┌──────────▼──────────────────┐
                    │            Nginx             │
                    │   静态资源 / 反向代理 / TLS    │
                    └──────┬──────────────┬───────┘
                           │              │
              ┌────────────▼───┐   ┌──────▼─────────────┐
              │  前台 SPA (Vue) │   │  后台管理 SPA (Vue) │
              └────────────┬───┘   └──────┬─────────────┘
                           │   REST/JSON  │
                    ┌──────▼──────────────▼───────┐
                    │        后端 API 服务          │
                    │  (Spring Boot，备选 Gin/Go)   │
                    └──────┬──────────────┬───────┘
                           │              │
                  ┌────────▼─────┐  ┌─────▼──────┐
                  │ PostgreSQL   │  │   Redis    │
                  │  主数据存储    │  │ 缓存/会话   │
                  └──────────────┘  └────────────┘
```

- 前台与后台均为独立 SPA，共用一套后端 API。
- 完整版原设计中内容（Markdown 正文）存于数据库、由后端接口输出；这与纯前端版现状（内容为构建期静态资产）的差异见 §5 注记。

### 4.2 后端选型：Spring Boot vs Go

| 维度 | Java（Spring Boot 3.x） | Go（Gin） |
| ---- | ---- | ---- |
| 学习曲线 | 较陡（注解、IoC、AOP），但体系成熟 | 语法精简，上手快 |
| 生态与中间件 | 极其丰富（Spring 全家桶覆盖安全、ORM、微服务） | 精炼够用，部分场景需自组装 |
| 中文资料与教程 | 最丰富，校招面试主线技术栈 | 快速增长，云原生方向强势 |
| 开发效率 | 中（模板代码偏多） | 高（代码量少，编译快） |
| 运行性能/资源 | 中等（JVM 内存占用较高） | 高并发场景优，资源占用低 |
| 部署 | JAR + JVM，镜像较大 | 单二进制，镜像极小 |
| 与平台内容的契合 | 平台源码可直接作为「Java 后端路线」实战范本 | 可作为「Go 路线」参考项目 |

完整版推荐：**Spring Boot 3.x + Java 17/21（主选）**；理由是国内 CS 学生主力就业栈、安全/ORM/任务调度等能力有成熟组件、平台「教什么就用什么」。Gin + GORM 为备选，架构与接口契约不变。Python (FastAPI) 仅作为独立微服务备选（如未来接入智能问答），不作主后端。

### 4.3 数据库与基础设施

| 项 | 完整版方案 |
| ---- | ---- |
| 主数据库 | **PostgreSQL 16**（JSONB、全文检索、窗口函数；内容的结构化元数据与正文均存于此） |
| 缓存 | Redis 7（热门内容缓存、会话/Token 黑名单、计数器） |
| 全文检索 | 先用 PostgreSQL 内置全文检索，量大后评估 Elasticsearch |
| 开发环境 | Docker Compose 一键拉起 PostgreSQL + Redis |
| 生产部署 | 云服务器 + Docker Compose（Nginx / API / PostgreSQL / Redis）起步，规模增长后评估 Kubernetes |
| CI/CD | GitHub Actions：推送触发测试 → 构建镜像 → 部署 |

与学习目标的兼容（完整版原注）：平台主库用 PostgreSQL，课程内容中提供 MySQL 对照知识点（两者 SQL 共通度高），实验环境可提供 MySQL 实例供练习。

## 5. 数据模型基线（完整版 §7 摘录）

| 实体 | 说明 | 纯前端版现状 |
| ---- | ---- | ---- |
| User | 用户（email、password_hash、nickname、role、status） | **无**——本地档案，无身份概念 |
| Progress | 学习进度（user_id + lesson_id 唯一约束，learning/done） | localStorage 版本化 schema |
| UserAnswer | 作答记录（question_id、answer、is_correct） | localStorage，日志型数据设条数上限 |
| Favorite | 收藏（course/lesson/path） | localStorage |
| Feedback | 内容纠错反馈（pending/resolved） | **无**——无上报通道 |
| Note / Comment（P2） | 学习笔记 / 评论 | **无** |
| Domain / LearningPath / PathStage / PathItem | 领域、路线、阶段、节点 | `content/domains.json`、`content/paths/` |
| Course / Chapter / Lesson | 课程、章节、知识点（content_md、est_minutes、status） | `content/courses/`、`content/lessons/`（MD 文件 + frontmatter） |
| Resource | 知识点外链资源 | 散布于各 lesson frontmatter |
| Quiz / Question | 测验与题目 | `content/quizzes/`（67 个：20 课程自测 + 47 章节随堂） |

核心关系（完整版原文）：

```
Domain 1 ── N Course 1 ── N Chapter 1 ── N Lesson 1 ── N Resource
Domain 1 ── N LearningPath 1 ── N PathStage 1 ── N PathItem ── 1 Lesson
User 1 ── N Progress N ── 1 Lesson          （唯一约束：user + lesson）
User 1 ── N UserAnswer N ── 1 Question
Course/Chapter/Lesson/Quiz 通过 scope_type + scope_id 灵活关联测验
```

> **注记（评估视角，非结论）**：内容域实体（Domain / Path* / Course / Chapter / Lesson / Resource / Quiz / Question）在纯前端版中已由 `content/` 静态 JSON + 构建期 CI schema 校验完整承担。接入后端时「**内容是否迁库**」是关键决策点：
>
> - **迁库**：获得在线编辑、审核流、版本回溯（完整版 F8/F3.6/F3.7），代价是放弃现有 PR 工作流与静态托管的部分优势，运维复杂度上升；
> - **不迁（最小后端）**：内容继续走 Git 静态分发，后端只管用户域（User / Progress / UserAnswer / Favorite / Feedback），与纯前端版 §7 的本地 schema 构成同一契约的两套实现（local / remote），切换层已预留。
